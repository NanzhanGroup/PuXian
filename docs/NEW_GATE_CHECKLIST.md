# 新建「门」的落盘检查清单（M247 建立）

> M247（第 124 轮）。**来历**：M246 一轮里，**门自己犯了 3 个错**（缺陷 418/419/420），
> 全部**在门跑起来才暴露**。其中「负控注入点错 ⇒ 假绿」**M204 的门头早已登记过**，
> 但**没有机械化** —— 新门照样踩。
>
> 本清单把这些「踩过的坑」固化成**落盘前必查项**。
> ⚠️ 它不是判据的替代品，而是「写门时最容易忘的那几类事」的提醒；
> 能机械化的部分已由**守卫**覆盖（见 §七），剩下的靠这份清单。

---

## 一 生成器与产物

- [ ] **参数传递口径与 runner 一致**。反例：M231 的 runner 用
      `subprocess.run([pxi, drv], env={..., "M231_CASE": idx})` ⇒ 驱动器必须
      `env("M231_CASE")`；首版写成 `args()[1]` ⇒ 实测 `pxi drv.px 0` 报
      `io: 读取文件失败 0`（解释器把 `0` 当**脚本路径**）。
      **⇒ 落盘前必须「抽跑 3 例」验证**（否则整个门跑错，而症状指不到根因）。
- [ ] **产物无多余空行**：`"\n".join(src)` 与元素**尾部换行**别重复 ——
      缩进语言虽可容忍，但与模板形状不一致会让「产物逐字节一致」类比对失效。
- [ ] 生成物（`drv.px` / `cases.tsv` / `MODEL.tsv`）与生成器**同提交**，且**可复现**。

## 二 复用与 import

- [ ] **被 import 的模块必须有 `if __name__ == "__main__":` 守卫** —— 缺陷 418。
      反例：`three_tracks.py` 末尾是**模块级** `sys.exit(main())`
      ⇒ `from three_tracks import norm_err, run` **执行了整个对拍并 `sys.exit`**
      ⇒ 新脚本的后续代码根本没跑（**症状：日志里出现的是被 import 方的输出**）。
      ⭐ **本仓是系列复用模式**（`three_tracks.py` 同名 12 份、`gen_probes.py` 5 份、
      `negctl.py` 7 份 …），「新门复用同族 runner」正是踩这个坑的动作
      ⇒ 已由守卫机械化（§七）。**截至 M247 实测：判红 0 个**（唯一被指向的那份已有守卫），
      但**潜伏面 30 个**（顶层有 `sys.exit`、当前没被指向）—— 它们是「**复用前先加守卫**」的清单，
      跑 `python3 selfhost/check_pymain_guard.py` 即得最新名单（**不判红**，见该脚本头注的取舍理由）。
- [ ] **import 位置在最早使用之前**（M244 事故：插入点与替换区重叠 ⇒
      import 掉到两段中间 ⇒ `UnboundLocalError`）。

## 三 性能

- [ ] **例数 × 轨数 > 500** ⇒ 必须用 `selfhost/gate_par.py` 的 `pmap_records`
      （逐例 spawn 彼此无依赖）—— 缺陷 419（1092 次串行 ⇒ 实测 >120s 被终止）。
      见 `docs/` 与本仓 M244 的用法：门之间**仍串行**（PID 锁护栏），**门内**吃满核数。
- [ ] `timeout` 给够，且**失败时把日志尾打进 stdout**（否则门红了读不到原因）。

## 四 ⭐ 负控（**最容易假绿的地方**）

- [ ] **问一句：我打桩的对象，是谁在读？**

      | 打桩目标 | 谁读 | 需要注入吗 |
      |---|---|---|
      | `runtime/*.c` | **产物**（`pxc` 编出来的程序） | 否（重编产物即可） |
      | `selfhost/*.px` | **编译器源码** ⇒ 只有 `bootstrap/pxc` **重编后**才是新编译器 | **是**：`devbuild` → `/tmp/pxcdev` + `PX_PXC_BIN` 注入（解释轨对称：`PX_PXI_BIN`） |

      ⇒ 缺陷 420：打桩 `cg_stmt.px` 却用 `tools/px build`（**入库件** `bootstrap/pxc`）
      ⇒ **打桩成功但门仍绿** = 假绿。**M204 门头已登记这条纪律，新门仍踩。**
- [ ] 打桩后**必须重跑**并断言**判红**，不能只看「打桩成功（锚点唯一命中）」。
      措辞纪律：**「打桩生效」与「打桩被读取」是两件事。**
- [ ] **分类要能区分**：`anchor`（锚点找不到）/ `buildfail` / `devfail` / `green` / `red`
      —— **构建/重编失败不许落进 `green`**（否则「重编挂了」会被读成「判据没牙」）。
- [ ] **收尾**：源**逐字节还原**（快照 + `cmp`）+ **清理共享产物**
      （`/tmp/pxcdev`、`/tmp/pxidev` —— 留着打桩版会**污染后续用它的门**）。
- [ ] 负控锚点**落在生效处**：`main()` 里的 `X = not args.no_x` 会**覆盖**模块级默认值
      ⇒ 只改模块默认值等于没关（M209 / M214 各撞过一次）。

## 五 判据

- [ ] 至少一层**独立真值**（不依赖「三轨一致」）。
      本仓已多次证明「**三轨一致 ≠ 正确**」：M215（`//` 溢出）· M226（方法 arity）·
      M231（`str × int` 静默）· M232（真值性）· M245（词条归属）· M246（形态等价性）。
- [ ] **规模锚点**（例数下限）+ **清单源码派生 ⇄ 生成器双向一致**
      （少登记 = 探针面静默变窄；多登记 = 悬空条目，两个方向都判红）。
- [ ] **覆盖边界如实登记**（含「本门**不**覆盖什么」）—— 未登记的缺口比已登记的更危险。
- [ ] 复杂表达式**先抽成变量再判**：`chk` 类 helper 里的裸 `$1`/`$2` 会被 bash 展开
      （M213 立过，M231 重犯）。
- [ ] 提示文本**一律单引号**（双引号里的反引号会触发**命令替换** —— 全仓已踩 5 次）。

## 六 注册

- [ ] `selfhost/gates.registry.sh` + `.github/workflows/ci.yml` **双向同步**
      （唯一注册源，M243 建立）。
- [ ] 跑 `bash selfhost/check_gate_registry.sh` 复查（应 6/0 `GATE-REGISTRY-OK`）。
- [ ] CI 用 `--neg-skip`（负控通常要重编/重跑，太贵）。
- [ ] 新增 `.px` 语料 ⇒ **冻结门要重定基**（`emitc_freeze`）；改 `runtime/*` 或
      `selfhost/*.px` ⇒ **要重烘入库件**。两者都是「同提交」完成。
