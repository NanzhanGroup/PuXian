# 窄口径门的动态重跑结果（M342 · 台账第 1 条的执行与**被推翻**）

> 输入：`docs/GATE_FLAKINESS_AUDIT.md` 第三节列的 21 个「单发取样 + 驾驭活进程」门。
> 目的：把「偶发」变成命中率数字。结论先写在最前面：**126 次运行、0 次命中**，
> 而这个结果**本身就否掉了我原来的方法假设**（见第三节）。

## 一 两种条件各跑了一遍（都是串行/子集的「同一棵树」）

### 条件 A：串行单跑（`selfhost/flake_rerun.sh -n 3`）

```
21 门 × 3 轮 = 63 次       PASS 63 / FAIL 0 / TIMEOUT 0      总耗时 35 分钟
现场：/data/gatevm/m342/<门名>/run-{1,2,3}.log
```

### 条件 B：并发子集（`shard_run.sh 4 --only <21 门>`，4 分片 · net 隔离 · 每片 JOBS=2 · 绑核）

```
3 轮 × 21 门 = 63 次       每轮均「绿 21 · 红 0」· round rc=0       每轮约 7 分钟
现场：/data/gatevm/shard-<时间戳>/{shard1..4}.log · quiet.log
      /data/gatevm/m342/parallel/round{1,2,3}.log
```

**合计 126 次运行，0 次命中。** 逐门明细见文末附表。

## 二 缺陷 598：串行重跑器**结构上**复现不出这些偶发

M340 台账第七节第 1 条写的是「对 21 个窄口径门 `flake_rerun.sh -n 5` ⇒ 出门 × 命中率表」。
这一条在动手前就该被否掉，理由是**已有记录**（不是本轮才发现的）：

```
588 m120 C6   ：11 次里 1 次（全量门分片内）· 同树单跑 1 次 + 连跑 10 次全绿
589 m150 ④    ：分片下报红 · 单跑必绿
591 m128 C6   ：11 次受控尝试（含 8 CPU hog 负载）**一次没复现**
594 m319 负控A ：单跑 17 通过 / 0 失败
595 m278 [2]  ：单跑 14 通过 / 0 失败
596 m245 负控A ：单跑 28 通过
```

⇒ **6 个已定性偶发全部只在「全量门 4 分片并发」下出现，同树单跑必绿。**
我的重跑器是**串行**的 —— 它测的条件恰好是「一定绿」的那个条件。
这与缺陷 589（就绪判据≠被测通道）、584（UDP 探针测 TCP 回退）**同族**：
**观测条件 ≠ 现象发生条件**，只不过这次发生在「诊断工具」而不是「门」上。

处置：
1. 登记缺陷 598；`flake_rerun.sh` 头注释已写明「串行 ⇒ 只测单跑稳定性」；
2. 给 `shard_run.sh` 加 `--only` 子集档（复用同一套 unshare/worktree/绑核/超时机制），
   让「并发条件重跑」不必跑 235 门全量（2h）也能做（7 min/轮）；
3. 前提自证（见第四节）—— 这次的负控**当场抓到两个真问题**。

## 三 126 次 0 命中，到底说明了什么（说清能证的和不能证的）

**能证的**：在「这 21 门子集 + 4 路并发」这个条件下，命中率 < 1/126。

**不能证的**：这些门在全量门里不会偶发 —— 本次条件与真实全量并发**不等价**：
```
全量 235 门  : 4 片 × 53–73 门/片 · 每片串行 50+ 门 · 共享 .rtcache/CPU/磁盘 IO · 单轮 2h
本子集 21 门 : 4 片 × 4–6 门/片  · 单轮 7 min · 竞争强度低一个量级
```

**一条推断（标为未证）**：若这些门自身以 5% 的概率偶发，126 次里应期望约 6 次命中，实测 0。
⇒ 更可能是**运行环境（全量并发下的资源竞争）**触发，而不是这些门的判据本身「单跑就不稳」。
这条要验，只能在**全量门条件下**做（下一轮）。不许把「0 命中」读成「这些门是干净的」。

## 四 `--only` 的前提自证（负控当场抓到两个真问题）

加 `--only` 时写了三条前提断言，全部实测：

```
① 门名必须在 HEAD 注册清单里，否则 exit 4（不许降级成「跑剩下的」）
   负控：--only m245_tls_cert_reload,no_such_gate ⇒ **rc=4** + 指名「no_such_gate」✅
   正控：--only m245_tls_cert_reload,m150_tls_crypto ⇒ rc=0、子集 2/235 门 ✅
② quiet 档必须收敛到子集内（否则「跑 21 门」会悄悄多跑 10 个低负载门）
   实测：`（--only 子集：quiet 档收敛为「m295_quic_slot,m296_quic_accept_reuse」）`
③ 出网门自动挪到 shard1 的逻辑**只能对本次要跑的门生效**
```

★ 第 ③ 条第一次跑就抓到 bug：
```
--only m245,m150 --dry 打出「shard1: 2 门」—— 多出来的正是 upstream_tests
根因：net_needed.txt 里的门**无条件**被塞进 shard1，不看本次子集
⇒ 已修：want = want ∩ 本次实际门集
```
★ 同时修掉一个**假读数**：`wc -l` 把「空分片的一个换行」数成 1 门 ⇒ 打过
`shard3: 1 门`、实际 0 门；改成数非空行（`grep -c .`）。两处：dry-run 打印 + 「shard$i 启动」行。

★ 另有一处**我自己的操作错误**：第一次跑子集用了目录名 `m131_http_stream_post`，
而注册名是 `m131_stream_post` ⇒ 三次全部 rc=4、`ALL_DONE` 却打印「正常结束」。
**是前提断言（①）把它拦下的，不是我发现名字错了** —— 这就是第 ① 条存在的意义。

## 五 下一步（按证据排，不按猜）

1. **在全量门条件下做频次统计**（唯一等价条件）：全量跑 N 轮，记每轮红门；
   代价 2h/轮 ⇒ 只能作为「守夜任务」跑 1–2 轮，不能每轮都做。
2. **资源竞争假说**的具体验证（不跑全量也能做）：给子集并发**加负载**（CPU hog / 磁盘 IO）
   再跑 3 轮 —— 若此时开始命中，就证到「竞争强度」这一维（当前子集并发没有这一维）。
3. **判据侧先修不依赖复现的那部分**：m245（596）负控 A 按 m319（594）的先例改成
   「N 轮内任一命中即判红」—— 这不需要复现，是**结构改进**，且能直接降假红概率。
