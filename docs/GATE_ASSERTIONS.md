# 门层判据守卫 —— 打桩锚点在位 + 判据串在场（M285）

> 本文是 `selfhost/check_gate_assertions.py` 的**口径文件**：它判什么、为什么这么判、
> 哪一段历史把口径逼成现在这样、以及**它刻意不看什么**。
> 共用原语在 `selfhost/shellscan.py`；编排层的那一半在 `selfhost/check_orchestrator.py`（M284）。

## 0 一句话

**判据自己也需要判据。** 一个门可以「永远绿」或「永远红」而没人知道 ——
本文处理其中两类：**负控被打桩打空了**（A1）与**判据串压根不存在**（A2）。

## 1 A1 —— 打桩锚点在位（本轮最有价值的一条）

### 1.1 形状

负控的标准打桩法是

```bash
sed -i 's|OLD|NEW|' runtime/runtime.c     # 把源码改成"坏"的，验证门会判红
```

**`sed` 在 `OLD` 找不到时 `rc=0` 且什么都不做** —— 不报错、不警告。
于是：源码改过了、`OLD` 没了、打桩**静默失效** ⇒ 负控**没有牙** ⇒
门照样打 `✅`，而它**根本没有测到任何东西**。

> M230 的原话：**「锚点失配不会报错，只会静默失效」**。
> M161 / M164 / M213 / M226 / M227 反复撞过同一形状。

### 1.2 判据

`sed -i 's<d>OLD<d>NEW<d>…' <目标>` 里，**`OLD` 必须在 `<目标>` 里**。
否则判红，并**指名**（目标文件 + OLD 前 80 字符）。

### 1.3 两个必须做对的细节（都踩过）

| 细节 | 不做会怎样 |
|---|---|
| **多层引用展开**：`shell_dequote`（双引号层）· `unesc`（BRE→字面）· `bre_to_ere` | 假红。实测 m191:140：`nc_static "…" "…" "sed -i 's\|\( *\)px_error(…)\|…' '$CO'"` 处在**外层双引号**里、再由 `nc_static` **eval** 一次 ⇒ 源码写 4 个反斜杠、到 sed 手里只剩 1 个 |
| **BRE→ERE 是双向的** | 假红。`\(` `\)` 在 BRE 里是**分组**、`(` `)` 在 BRE 里是**字面** ⇒ 只做一半会让 `px_error(` 的括号被 ERE 当分组 ⇒ 匹配失败（真锚点在 `coro.c:836`） |

判据用**多形态任一命中**（方向 = **放宽**，fail-safe）：宁可漏报，不制造假红。

## 2 A2 —— 判据串在场（把 M284 的 O1 推到门层）

### 2.1 形状

**缺陷 495**（M284）：watcher 里写 `grep -qE '双路判据一致：0 红'`，而**全仓 0 命中** ——
门明明是绿的，判据串是**凭空捏造**的。M284 在**编排层**收了口，
并如实登记：「门的判据串刻意未覆盖」（当时实测多出来的一批是假阳）。
**可那句凭空串恰恰长在门那一侧** ⇒ M285 把它推到门层。

### 2.2 判据（两条互补）

| | 条件 | 覆盖 |
|---|---|---|
| **目标在场** | grep 的**文件操作数**可解析到仓库内文件 ⇒ 串必须**在该文件里** | 源码锚点自查（`grep '锚点注释' runtime/runtime.c`）· 文档自查（`grep '事实 N' docs/…md`） |
| **在场兜底** | 目标不可解析（管道 / `$W` 生成物 / `/tmp`）⇒ 串必须在**代码或夹具**里存在 | 门自产消息（先 `echo` 后 grep 日志）· 夹具数据（`pxdoc` 读 `.px` 的 doc 注释）· `tools/px`（**无扩展名**脚本，pathspec 匹配不到，单独列） |

两不过 ⇒ 判红。

### 2.3 三条**刻意不看**（都是为了 0 假红）

1. **散文文档不进兜底面** —— `*.md` / `CHANGELOG` 被**排除**。
   理由（M284 v2 实测）：我在 CHANGELOG 里引用「这个串不存在」⇒
   `git grep` 立刻找得到 ⇒ **判据自己把反例变成正例**。
   ⇒ 排除散文之后，本判据**免疫自指**。
2. **反向断言跳过** —— `if grep …; then bad` / `&& VAR=1` / `|| true` / `!` 都是
   「**期望该串缺席**」的断言（真仓里有：m245 断言旧口径已清除、m263 断言旧措辞已清）。
   方向读错了会**系统性假红**。
   ⚠️ 动作常写在**下一行**（`if grep …; then` ↵ `  bad "…"`）⇒ 断言方向必须带 2 行上下文。
3. **同文件打桩后的状态跳过** —— m201 的形状：先 `sed -i` 改 `runtime.c`，
   再 `grep` **打桩后的新串**。那个串当然不在**原始**文件里。

## 3 顺带收口 —— 缺陷 498：抽「pattern」抽错了参数

原实现：

```python
GREP_RE = r'\bgrep\b[^\n|;]*?\s(?:-e\s+)?[\'"]([^\'"\n]{4,})[\'"]'
```

它要求串长 `≥4`，于是**短 pattern 被跳过**、正则继续往后找 —— 抓到了**行尾的消息参数**：

```bash
chk "$(echo "$OUT" | grep -c '可复现')" "1" "--locked 可复现构建确认"
#                                          ↑ 真 pattern      ↑ 被抽到的"判据串"
```

**判据在错误的串上做** —— 门层实测制造 **8 条假阳**。

修法（**顺序反了就会抽错**）：**先取 pattern，再做长度/中文过滤**；
pattern = `grep` 自己的选项之后的**第一个 token**（不是「行内第一处引号串」——
`grep -q .; then ng "消息"` 的真 pattern 是 `.`）。

⚠️ 同一个坑在**两个守卫里各踩了一遍**（`check_orchestrator` 与 `check_gate_assertions`）
⇒ 判据抽成**共用原语** `selfhost/shellscan.py`：**一条规则只许出现一处**
（M234 缺陷 352 同族：同一条规则两处实现 = 结构性分叉隐患）。

### 3.1 `mask_prose` —— 「`grep` 只是被**提到**」

真仓实测两处假阳，都是**散文里的 `grep`**：

```bash
iv_nopipeq() { # … 无「大产出 | grep -q」禁形（**只查代码行**…）   # ← 注释里
iv_bad "… 注入 tar|grep -q 竟未被发现（判据无牙）"                # ← 消息里
```

⇒ `mask_prose` 把「行内注释 + 引号里的普通文本」抹成**等长空格**：

- 定位用 **masked**（散文里的 `grep` 不算命令）
- 解析用 **原始行**（掩码会把引号里的 sed 脚本一并抹掉）

⚠️ 但 `chk "说明" "grep -q …"` 里的 `grep` 是**真判据**（`chk` 会 eval 第三个参数）
⇒ 「引号内容以 `grep`/`sed`/`!` 开头」⇒ **保留**。

## 5 覆盖边界（**如实登记**：知道自己在哪儿不看）

- **A1** 只判**目标可解析到仓库内文件**的打桩（40 处里 22 处）。目标是 `$W/xxx`（运行期生成）
  或 `/tmp/…` 的**不在判据内** —— 那是「改内存里的产物」，没有静态在场可言。
- **A1 的「在场」是放宽的**（多形态任一命中）⇒ 极少数「形态碰巧命中」的失配会**漏报**。
- **A2 只覆盖中文（CJK）判定串**；纯 ASCII 的（`grep -q PASS`）**未覆盖** ——
  与 M284 的 O1 同口径（它们可能来自第三方工具，全仓在场性不成立）。
- **A2 跳过反向断言与打桩后状态** ⇒ 这两类里的真「凭空串」也不判。
  **知道自己在哪儿不看，好过假红**（M283 纪律：口径校准到 0 误伤）。
- **恒真判据**（`grep -q .` 恒匹配）**不判** —— 那是另一条判据（下一轮候选）。
- **`mask_prose` 的「引号里是命令」判据**是启发式（引号内容以 `grep`/`sed`/`!` 开头）⇒
  形状变了要同步（门 `[5]` 有两条「必须不红」的正例护着）。

## 6 复发预防（写给未来的自己）

1. **改任何 `sed -i` 打桩的锚点** ⇒ 立即想「负控还有牙吗」。本守卫会在全量门里兜住。
2. **改 `examples/**` 的判据串** ⇒ 想「这个串还有生产者吗」。
3. **门源码里出现自己要在夹具里用的「凭空串」** ⇒ 用**码点拼装**
   （守卫 `FIXTURES` 与门 `[5]` 都这么做）—— 否则判据**自己把反例变成正例**。
4. **同一条规则**不要在两个守卫里各写一遍 ⇒ 进 `shellscan.py`。
