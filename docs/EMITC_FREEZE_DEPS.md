# 发射冻结门 · 类别 B 的已知盲区：传递依赖（M313 归因留档）

## 症状
改了 registry 里的模块（如 registry/mysql/0.2.0/mysql.px），
import 它的用例（examples/m313_mysql_driver/probe.px）会被判「类别 B · 发射行为回归」：
入口 .px 的 src 指纹没变，但 emit-c 输出变了。

## 为什么
emitc_freeze.sh 的源码指纹只对**入口文件**做 sha256，import 的模块不在指纹里。
于是「依赖模块有意改」与「发射路径回归」在判据上不可区分。

## 本次（M313 · HEAD 1924038）实测
- probe.px out 48e52a19… → 336707b5…（rc 都是 0）
- 隔离法：同编译器 + 同 probe.px，仅把 mysql.px 换回 304db24 ⇒ 差异**完全消失**
- 240 行差异全部来自 mysql.px：字符串前缀 "mysql: " 2 条 + mysql_ping / mysql_select_db
  的槽位与指令数（nslots 44→32 / 56→44）
⇒ 非发射回归；按门文档「有意改发射 ⇒ --freeze + 说明」重定基（482 件，仅 1 行变化）。

## 待办（M314）
1. 源码指纹升级为**传递指纹**：入口 + 递归 import 的 sha 合并后再算；
2. 重定基时输出「差异行 → 所属模块」的归因提示，减少人工排查。

# M398 收口（2026-11-13 · 缺陷 761）· 上面两条待办都已落地

> 为什么拖了 84 个里程碑才做：它不是产品缺陷，是**判据缺陷**——门红的时候人总会先怀疑
> 产品。M397 之前两天内它造成了**两次**误判（一次 `--freeze` 漏重定基下游 golden、
> 一次全量门假红 1 门），两次都靠「只换被 import 的文件、其余不动」的对照实验才定性。
> 判据骗人的成本最终超过修判据的成本，所以这轮停下来修它。

## 一 影响面（先量再改）

```
门口径：ls selfhost/cases/*.px examples/*/*.px  ⇒ 524 个入口
有传递依赖（闭包 >1）            50 个
被依赖最多的公共模块             stdlib/strings.px（18 个入口）
                                 stdlib/gfx.px（5）· stdlib/pxml.px（4）
                                 selfhost/value.px（v01_value 等）
解析不到的 import                 10 条（含 `import "c/xxx"` C 库绑定、Python 风格的多名
                                 import、生成代码里的拼接 import）
```
⇒ 改 `stdlib/strings.px` 一行，旧口径就会让 **18 个入口**同时落进【类别 B · 必须查】。

## 二 新口径（实现在 `selfhost/freeze_deps.py`）

```
dep = sha256( "E <入口路径> <sha16(入口)>"
              + 每个依赖 "D <路径> <sha16>"
              + 每条解析不到的 "U <import 字面量>" )[:16]
```
三条设计要点，每条都对应一次实测踩坑：

1. **入口必须计入 dep**（不只是依赖）。否则「零 import 的入口」dep 退化成常量，
   源码一改就被判成【类别 B · 源码未变而产物变】——把误报从「有依赖的文件」平移到
   「无依赖的文件」，等于没修。门内 **T3** 专测这一条。
2. **解析不到的 import 把字面量拼进指纹**。`import "c/xxx"` 是 C 库绑定（M42，不加载 .px），
   生成代码里的拼接 import 也解析不到 —— 但这两种**改一个字也该让指纹变**。
   保守方向是「宁可多算不可少算」：多算只多一点重定基，少算就是缺陷 761 本身。
3. **解析规则照抄编译器**（`selfhost/cg_module.px:cg_find_module_path`），不自己发明：
   相对路径 / `std.*` → `<repo>/stdlib/x/y.px` 或 `.../mod.px` / `x.y` → `.px_modules` 子目录。

## 三 基准格式与兼容

```
旧   <file> src=<entry16> rc=<n> out=<32> err=<16>
新   <file> src=<entry16> dep=<closure16> rc=<n> out=<32> err=<16>
```
- 判据列**仍是** `rc/out/err`（产物）；`src`/`dep` 只用于**分类**，不单独判红。
- 类别分界：`dep` 变 + 产物变 ⇒ **A**（源码闭包已变）· `dep` 未变 + 产物变 ⇒ **B**（真回归）。
- 旧基准（无 `dep` 列）⇒ 自动退回入口 sha 分类，**不崩、不假红**，并打印升级提示（门内 T8）。
- 本次重定基自证：新旧基准去掉 `dep` 列后**逐字节相同** ⇒ 524 行的 `rc/out/err` 一字未动，
  只多一列（不是橡皮图章）。524 行 524 个唯一 `dep`（无重复）。

## 五 门 `m398_freeze_deps`（23 条判据）

```
T1 幂等          同一入口两次 sig 完全一致
T2 传递性有牙    注入 selfhost/value.px ⇒ v01_value.px 的 src 不变 / dep 变
T3 无依赖有牙    注入 s01_arith.px（零 import）⇒ 它自己的 dep 变（防常量假绿）
T4 未解析 import 改字面量 ⇒ dep 变
T5 【B 必须红】  wrapper 篡改 v01_value 的 --emit-c 输出、**源码一行不动**
                 ⇒ rc=1、报【类别 B · 发射行为回归】、该文件落在 B 段、A 段为空、有归因
T6 【A 不误判】  注入 value.px ⇒ rc=1、落在 A 段、**B 段为空**（缺陷 761 的收口点）
T8 旧格式兼容    基准缺 dep 列 ⇒ rc=0（不假红）+ 提示升级
T9 收尾自证      value.px / s01_arith.px 已还原、真二进制 bootstrap/pxc_vm 未被替换
```
负控自证（开发期实测）：把 `freeze_deps.py` 的依赖循环改成空（== 旧口径）⇒ 门红 3 条
（T2 dep 未变 / T6 落进 B 段 / T6 B 段非空）⇒ 本门确实测的是缺陷 761 的缺口，不是恒绿。

**约束**：全程不替换 `bootstrap/pxc_vm`（用 `EMITC_BIN` 指向 wrapper）——
替换真二进制在中断时会毁掉工具链；所有注入先备份、trap 恢复、结束时校验还原。

## 六 仍然不覆盖的东西（诚实边界）

- **不做**「差异行 → 所属模块」的**逐行**归因（待办 2 的强解读）。逐行归因要编译器在
  emit-c 时携带「本行来自哪个模块」的元信息，属于发射路径改动（会改所有产物）。
  本轮给的是**文件级**归因（闭包清单 + git 最近提交），对「我只改了一个文件」的场景够用。
- `emitc_freeze.sh` 新增的三个 env（`EMITC_FREEZE_FILES` / `EMITC_FREEZE_GOLDEN` / `EMITC_BIN`）
  是**为门服务的可测性接缝**，生产与 CI 一律不设；误设的后果是「门只看子集」——
  这一点由 `check_gate_registry` 与全量门的口径（不设任何 env）共同约束。
- 闭包解析是**文本级**的，不跟进条件 import / 运行时拼路径。这两类在仓内不存在
  （实测 524 入口里 10 条解析不到的已全部计入字面量），若将来出现，指纹会偏保守（更容易判 A）。
