# 普贤运行时诊断 · 错误码与「域前缀族」权威口径（M191 建立）

> **本文地位**：运行时错误的**单一真相**。`docs/spec.md` §11.2 面向用户保留一张简表；
> 两者冲突时**以本文为准**（M191 前 §11.2 把「参数个数不符」同时写进 R1002 与 R1005，
> 属表述自相矛盾 —— 现按 §2.3 定档）。
>
> **判据化**：本文的每一条都由 `examples/m191_error_codes/` 的**静态判据**（扫 `runtime/*.c` +
> `selfhost/*.px` 的每个出错站点）与**动态判据**（三轨实跑对拍同码同文）强制。

---

## 1 一个错误该不该带 R 码？—— 只看「谁决定了这个失败」

| 决定失败的因素 | 归类 | 形态 | 例 |
|---|---|---|---|
| **用户表达式自己的**值 / 类型 / 形状 / 实参个数 | **语言层** ⇒ **必须带 R 码** | `R10xx: <消息>` | `len(1.5)` ⇒ `R1002: len 不支持类型 float` |
| **OS / 文件系统 / 网络 / 后端库 / 资源上限** | **库·环境族** ⇒ **不带码**，带**域前缀** | `<域>: <动作>失败 <对象>: <原因>` | `io: 打开文件失败 /tmp/x: No such file or directory` |
| **进程级致命**（panic / assert / 协程崩溃 / 栈溢出） | **进程级** ⇒ `R2xxx`，**不可捕获** | `R20xx: <消息>` | `assert(false)` ⇒ `R2001: 断言失败` |

**一句话**：用户改自己的代码就能避免 ⇒ 语言层（R 码）；只有换个环境/文件/网络/机器才能避免 ⇒ 库·环境族（域前缀）。

三条由此推出的**硬约束**（门会判）：

1. **语言层不允许"无码"** —— `px_error` 站点必须在 `R####` 与 §3 的域前缀**闭集**里二选一。
2. **域前缀族是封闭集** —— 新增域必须登记到 §3（否则门红），避免"每个模块自己发明一种前缀"。
3. **个数与值分码** —— 见 §2.3（同一条检查同时覆盖两者时**必须拆开**）。

## 2 码表

### 2.1 `R1xxx` —— 语言层（用户可预期，可改代码避免）

| 码 | 语义 | 边界（易混点） |
|---|---|---|
| `R1001` | 未定义名字 | 未定义变量 / 未注册的 native（含 `--no-xxx` 裁剪后不可达） |
| `R1002` | 值与形状不符 | 参数**类型**不符 / 字典键非字符串 / 解包形状不符 / 该类型不支持此操作（索引、方法、内置） |
| `R1003` | 越界与长度 | 索引越界 / `pop` 空列表 / 迭代期间被迭代容器长度变化（进入循环时的长度快照，spec §17.2） |
| `R1004` | 不可调用 | 值不可调用 / 枚举类型直接调用（须 `X.Variant`）/ `unwrap()` 失败（Err） |
| `R1005` | 调用**形状**错误 | **方法调用的实参个数**不符 / 字段过多 / 缺形参 / 非法控制流（`break` 在循环外…） |
| `R1006` | 数值域错误 | 除零 / 取模除零 / `range` step 为 0 / **切片步长为 0** / 负数间隔 / 端口越界 / 长度上限（数值型） |
| `R1007` | 类型无此成员 | 类型没有该字段或方法 |
| `R1008` | 缺键 / 缺字段 | 字典缺键、结构体缺字段（不静默返回 `null`） |
| `R1011` | 通道已关闭 | 向已关闭通道发送 / 从已关闭且为空的通道接收 |
| `R9001` | 引擎内部错误 | 正则节点类型未实现 · **VM 字节码/元数据越界**（`LOADK`/`GETG`/`SETG`/`NEWSTRUCT`/`CALLM` 等的槽位或名字下标越界 —— 字节码由编译器产出，越界即**编译器缺陷**，不该被用户触发） |

`R1009` / `R1010` **未分配**（历史留空，不要"顺手"占用）。

### 2.2 `R2xxx` —— 进程级致命（不可捕获，进程终止）

| 码 | 语义 |
|---|---|
| `R2001` | `panic(...)` 调用 / `assert(cond)` 失败（`assert(false)` ⇒ `R2001: 断言失败`；带消息 ⇒ `R2001: 断言失败: <msg>`） |
| `R2002` | 协程崩溃（未捕获错误） |
| `R2003` | 栈溢出 |

> **M191 的两处修正**：① `assert` 失败此前在**解释轨**被错标成 `R1003`（越界与长度）—— 语义完全不符，
> 现两侧统一 `R2001`；② `panic("x")` 此前两侧都只有裸消息（无码），现统一 `R2001: x`。

### 2.3 「个数」还是「值」？—— M191 定档（消除 spec §11.2 的自相矛盾）

实参**个数**与实际不符时：

| 调用形态 | 码 | 理由 / 例 |
|---|---|---|
| **方法调用** `x.m(...)` | **`R1005`** | 方法签名 = 「名字 + 个数」共同确定，个数错属**调用形状**错。`l.append(1,2)` / `s.upper(9)` / `l.len(9)` / `t.len()` / `Ok(1).unwrap(2)` |
| **函数 / 内置调用** `f(...)` | **`R1002`** | 参数**列表**的个数属"参数不符"。`unique()` / `Ok()` / `range()` / `assert()` / `time_format(1,2,3,4)` |

**混合检查必须拆开**（M191 起）：`if (nargs != 1 || args[0].type != PX_STR)` 这类**同时覆盖个数与类型**的
守卫，要写成两条 —— 个数 ⇒ `R1005`，类型 ⇒ `R1002`，各自给码（实例：`方法 find / has_prefix / has_suffix`）。

> **为什么不是「一律一个码」**：两侧（解释轨 `icall.px`/`ibuiltin.px` 与 runtime `px_method`/`bi_*`）
> 此前**各自**已经把方法族贯通为 R1005、内置族贯通为 R1002 —— 是**两轨一致的现行真相**；
> 若改成"一律"，需动 native 364 处 + 解释轨 ~200 处 + 13 处门断言，收益是「少一个概念」、
> 代价是大面积重定基。**登记为后续候选**（见 §5），本轮先**如实定档 + 判据化**。

## 3 域前缀族（库 · 环境）—— 闭集

这些错误的决定因素**不在用户表达式里**（文件不存在、端口被占、内核不支持、后端返回失败…），
因此**不带 R 码**，用**域前缀**分类。**新增域必须登记在此表**（门会判）。

| 族 | 前缀（代码里出现的形式） | 例 |
|---|---|---|
| **E1 文件 / I/O** | `io:` `fs:` | `io: 打开文件失败 /tmp/x: ...`、`fs: 读取目录失败 ...` |
| **E2 网络 / 传输** | `net:` `tcp_listen:` `udp_open:` `udp_serve:` `udp_send:` `tls_connect:` `tls_upgrade:` `tls_server:` `tls_server(...):` **`ws_serve:`**（M193） | `net: 监听端口 8080 失败`、`ws_serve: 绑定端口 9000 失败` |
| **E3 HTTP / SSE / 站点** | `http_serve:` `http_serve_unix:` `sse_serve:` `px_serve:` `vhost:` | `px_serve: 绑定端口 80 失败：Permission denied` |
| **E4 数据 / 解析** | `json:` `regex:` `zip ` **`XML 解析错误`**（M193） | `json: 期望对象键`、`XML 解析错误：缺少根元素` |
> ✅ **M193 起的闭环**：语言层**不许**借域前缀逃码（§3 末段）—— 反过来，**误用域前缀的语言层站点也要收回来**（M192 的 `zlib:` 2 处即此例）。解析失败取决于**输入数据**（不取决于用户代码）⇒ 与 `json:` 同族，属本族。 |
| **E5 资源 / 上限** | `spawn:` `定时器` `定时器:` `cron:` `cron …` `bus_subscribe:` `bus_publish:` `ctx_set:` `事件总线数量超出上限` `虚拟主机数量超出上限` `SNI 证书数量超出上限` `全局表溢出` `句柄表已满` `创建线程失败` `并发线程数超出上限` `内存不足` **`路由数量超出上限` `中间件数量超出上限`**（M193） | `spawn: 并发线程数超出上限 64` |
| **E6 进程 / 策略** | `os_exec …` `沙箱：` `%s: SO_REUSEPORT …` | `沙箱：函数 os_exec 已被禁用` |
| **E7 后端算法（几乎不可达）** | `md5 …` `sha1 …` `sha256 …` `pbkdf2_sha256 …` `hmac_sha1 …` `hmac_sha1_bytes …` `aes …` 计算失败（M202 补 hmac_sha1 两件） | `sha256 计算失败`（mbedTLS 返回非 0） |

**允许文本里带 `strerror` / errno 细节** —— 那是本族存在的意义（"为什么打不开"只有 OS 知道）。
**不允许**的是：语言层错误借域前缀逃避带码（例如"参数类型不对"写成 `io: ...`）。

## 4 门怎么保证（`examples/m191_error_codes/`）

1. **静态判据**：扫 `runtime/*.c` + `selfhost/*.px` 的每个出错站点 ——
   ① 必须带 `R####` **或**命中 §3 的域前缀正则闭集；
   ② 「个数类」站点按 §2.3 判码（方法 ⇒ R1005 / 其余 ⇒ R1002）。
2. **动态判据**：30 个探针 × **三轨**（解释 / VM / C）实跑，判 `rc≠0` + **同一 R 码** + **同一正文**。
3. **负控**（各自独立判红）：去掉一个 R 码 / 把某个域前缀改名 / 把方法个数码改回 R1002 /
   撤销一处混写拆分 —— 任一条都必须让对应判据由绿转红。
4. **判据 ⑥（M194 新增）· 参数类型守卫完备性**：对每个 `px_error("R1002: <fn> 需要 (<a>, <b>…)")`
   站点，其**函数体**里每个被使用的形参位置都必须有 `args[i].type` 检查（口径见 §6）。
   实测基线（M195 后）：**137 个多形参守卫 · 缺检查 0**
   （140 → 137 的原因：h3/quic listen 族的元数消息改成「需要 (port) 或 (port, cert, key) 参数」，
   扫描器只取第一个 `)` 之前的形参 ⇒ 这几处不再计入「多形参」；站点本身仍在，由 [S6] 全文覆盖）。
5. **判据 ⑦（M195 新增）· 全部 native 函数的参数守卫 + 豁免表**：口径同 §6，但覆盖
   **全部 397 个** `LXValue fn(LXValue* args, int nargs, …)`（含单形参、含消息不列形参的形态）；
   只统计**宽松接口**（`int_val` / `num_val` / `val_cstr` / `px_val_cstr` / `.as.obj->as.*` / `.as.i`），
   校验型接口（`px_req_*` / `px_arg_*` / `px_val_is_*` / `math_num` / `px_len` / `px_index`）算已检查。
   实测基线：**397 个函数 · 未豁免缺检查 0 · 豁免 24/24**。
   豁免表 `ARG_GUARD2_EXEMPT` 三条强制：① 表内每条的函数须在源码里**找得到**（防改名后漂移）；
   ② 豁免**总数棘轮**；③ 理由字段非空。

## 5 已知差异（诚实登记）与后续候选

1. **未收口清单 —— 已清零（M193，第 71 轮）✅**

   收口进度：**264 → 143（M192 第一批 121）→ 0（M193 第二批 143）**。
   `examples/m191_error_codes/scan_errcodes.py` 的 `UNCODED_BASELINE` **已清空** ——
   表为空即等价于「**全仓无未收口站点**」：此后任何新增无码站点**立即判门红**
   （不再是棘轮，而是硬判据）。

   M193 收口明细（12 文件 / 143 站点）：

   | 分类（§1） | 处置 | 处数 |
   |---|---|---|
   | 语言层（实参类型 / 形状不符） | 补 **`R1002`**（§2.3：函数/内置） | 102 |
   | 调用**形状**（缺形参） | 补 **`R1005`**（与解释轨 `调用 f 缺少参数 'b'` 同码） | 2 |
   | `unwrap` 失败（`!` 强制解包） | 补 **`R1004`**（与解释轨 `unwrap 失败: Err(x)` 同码） | 2 |
   | VM 内部一致性（字节码/元数据越界） | 补 **`R9001`**（出现即编译器缺陷） | 18 |
   | 库·环境族 | **只登记域前缀、不改文本**：`ws_serve:`(3) · `XML 解析错误`(13) · `路由/中间件数量超出上限`(2) | 18 |
   | 转发点（透传上游已带码消息） | **豁免表**（见下） | 1 |

   **转发豁免机制（M193 新增）**：极少数站点形如 `px_error("%s", msg)` —— 消息文本来自
   **上游已带码/域前缀**的缓冲区（例：`runtime/coro.c:804` 透传 `px_native_call_capture` 的
   `errbuf`）。这类站点静态上看不见码，故设 `FORWARD_EXEMPT` 表，**每条必须给理由**，并由判据强制：
   ① 表内每条都要在源码里**找得到且形态匹配** `px_error("%s"`（防「代码改了表没改」）；
   ② 豁免**总数不得多于**登记数（棘轮）；③ 理由字段非空。

2. **渲染框架不同（设计如此，不是缺陷）**
   - 解释轨（`px run` / `bootstrap/pxi`）由**解释器自己**抛的错误：`运行时错误: 错误 [R1002] 行:列: 消息`（带用户行列）。
   - 编译轨（VM / C）：`运行时错误 [<函数> 行N]: R1002: 消息`（带 `.px` 源行号）。
   - ⚠️ **解释轨里由 native（C 层 `px_error`）抛出的错误**，因为 `px_error` **不可捕获**（直接终止进程），
     渲染出来的是**解释器自身**的函数/行：`运行时错误 [i_call_builtin 行496]: ...` —— **拿不到用户行**。
     要按用户行定位请用**编译轨**，或用 `*_opt` / `Result` 变体自己接错误。
     （门的动态判据因此只判「同码 + 同文」，**不判位置框架**。）
3. **解释轨的 Mini 子集边界**：`mutex` / `rwlock` / `chan` 等并发原语在解释轨**不支持**
   （`R1002: interp 不支持通道（Mini 子集排除）`）—— 有意不做，非缺陷。
4. **后续候选（未做，已在 §2.3 说明代价）**：把所有"实参个数"统一为单码。

## 6 native 参数**类型守卫**口径（M194 建立 · 缺陷 222）

> **主问题**：`R1002` 只保证"错了会说"，**不保证"错了一定会被说"**。M191–M193 把
> "出错站点是否带码"收口到 0 残留，但**守卫本身可能不存在** —— 26 个站点"形参 ≥2、
> 却只查了个数或只查了首参"，其余实参直接进 `int_val()` / `val_cstr()` / `.as.i`：
> 三轨**一致地**给出**静默错值**（不是分叉，是共享缺陷，用户无从察觉）。

### 6.1 判据 —— 按「实参被怎么用」决定是否必须检查

| 用途 | 判定 | 不检查的后果（修前实测） |
|---|---|---|
| **容器**（`.as.obj->as.{list,dict}` / `px_list_*` / `px_dict_*` / `px_bytes_*` / `px_index` / `px_len`） | ✅ **必须** | 读 union 的其它字段 ⇒ **UB / 段错误** |
| **整数**（`int_val()` / `.as.i`） | ✅ **必须** | ① `int_val` 对 float **静默截断**：`read_at(p, 1.5, 3)` == `read_at(p, 1, 3)`；② **`.as.i` 更糟** —— 把 float 的**位模式**当整数读（`1.5` ⇒ `0x3FF8000000000000` = 4609434218613702656，h3 族直接当 poll 超时用） |
| **数值**（`num_val()` / `math_num()`） | ✅ **必须** | 同 M179（读 union 的 `as.f`） |
| **字符串**（`val_cstr()` / `.as.obj->as.str.data`） | ✅ **必须** | **静默串化**：`s3_get(1,2,3,4,5)` ⇒ 对 endpoint `"1"`、bucket `"2"`… 的请求；`s3_put` 的 `data` 更是把 `<object>`/`null` 当正文上传 |
| **仅用于错误消息**（`px_type_name(args[i])`） | ❌ 豁免 | —— |
| **输出/串化汇**（`px_to_string`，如 `write_file` 的 `content`） | ❌ 豁免（**设计如此**：任意类型都是合法语义） | —— |
| **`[可选]` 形参** | ⚠️ **「存在即校验」** | 见 §6.3 |

**统一文案**（与 M179 的 `px_req_int` / M189 的 `px_req_int_idx` 同族）：

```
R1002: <函数> 的 <参数> 需要<类型>，实际是 <t>
```

实现入口（`runtime/runtime.h`，非 static ⇒ 各模块可见）：

```c
int64_t    px_arg_int(LXValue v, const char* fn, const char* pname);
const char* px_arg_str(LXValue v, const char* fn, const char* pname);
const char* px_arg_strbytes(LXValue v, const char* fn, const char* pname);
LXObject*  px_arg_dict(LXValue v, const char* fn, const char* pname);
```

### 6.3 可选实参：「**存在即校验**，`null` = 未提供」

- 形参写成 `[x]` / `x?` 时，**用户可以不传**；但**传了就得是那个类型**。
- 修前 `http_request(u, "GET", 123)` **静默丢掉** body、`px_serve(9000, ".", opts)` **静默丢掉** opts
  —— 与 M190 的 213-b（`d.set("b")` 写入 `null`）同族：「写了参数却什么都没发生」。

### 6.7 「同码文案」的三轨单一真相（M196 收口）✅

### 6.7a 判据 [S8]：**全内置 0 参探针**（M197 建立 —— 补 [S7] 的盲区）

**[S7] 的盲区**：它是**静态**对拍，比的是「解释轨的**字符串字面量**」⇄「原生的字面量/模板」。
但解释轨有一大类文案是**用变量拼出来的**（`cname + " 需要 1 个参数"`、
`"方法 " + name + " 需要 1 个参数"`）—— 字面量的 **head 是变量**，静态器只看到
`" 需要 1 个参数"` 这种**无 head** 的碎片 ⇒ 归不到任何函数名下 ⇒ **看不见**。

**补法（[S8]）**：把**每个内置**都拿 **0 个实参**调一次：
1. 必须得到 **`R1002`**（0 参 = 个数错）—— **不是 R1002 就是「守卫顺序」错**
   （修前实测：`gen_next` / `os_spawn` / `os_kill` / `os_exec` 都撞 `R1003 索引越界`）；
2. 文案必须**逐字命中**原生侧该函数的某条 arity 文案。
名册 = **单一事实源** `selfhost/interp.px` 的 `names` 列表（193 个）；
0 参**合法**或**有副作用**的 24 条列入 SKIP（**每条给理由**）；
原生文案从**源码**读 ⇒ 改原生文案**不必重烘**即可让判据变红。

> **可复用的判据**：**「守卫顺序」的判定 = 拿 0 个实参调一次** ——
> 若报的不是 arity 错，就是顺序错（守卫跑到了取实参之后）。

### 6.9 native **元数上界** 与 **时长族** 的单一真相（M198 建立 · 缺陷 234/235 + 229）

**判据 [S9]（元数上界 · **硬判据**，无棘轮）**：注册表里的**每个** native 必须满足二者之一：
① 函数体里**显式声明上界**（`nargs != N` 或 `nargs > N`）；
② 在**真变长豁免表**内（`examples/m198_argface/sweep_upper.py` 的 `VARIADIC`，**每条给理由**，

**文案逐字不动**（`== / <` → `!=` 只改边界，不改消息）⇒ 不打扰 M196 [S7] / M197 [S8]。

## 6.10 逐参类型守卫的「**声明 ⇄ 生效**」与**三元兜底禁令**（M199 建立 · 缺陷 237/238）

### 6.10.1 为什么需要这一面

M190 量「实参**个数**」· M194/M195 量「**单个**实参的类型守卫」· M197 量「0 参 ⇄ arity 文案」。
**没有任何一门量过「同一操作 × 每一个位置 × 错类型」**。本轮把这个面补上后，实测到两种形状：

| 形状 | 机制 | 实测（解释轨 ⇄ 编译轨） |
|---|---|---|
| **三元兜底** | `(nargs >= 2 && args[1].type == PX_STR) ? args[1]… : " "` 把「**不是**字符串」与「**缺省**」混为一谈 | `split("s", {})`：解释轨 `R1002 split 参数需要 string` ⇄ **编译轨 rc=0 输出 `[s]`**（静默） |
| **入口不同** | 解释轨的 `ibuiltin.px` 分支经**方法面**执行（`args[0].replace(a,b)`）⇒ 位置错时报的是方法面词条 | `replace({}, "a", "b")`：解释轨 **`R1007 类型 dict 没有方法 'replace'`** ⇄ 编译轨 `R1002: replace 需要 3 个字符串参数` |

⇒ 两条规则：

**(1) 三元兜底禁令（[S10-a]）**：`args[P].type == T ? A : <默认>` 只允许出现在
  - 同一 if/else-if 链的**末支** `else px_error(...)` 之前（类型分派，静默不可能），或
  - 该表达式**之后/之前**另有对同一位置的**显式守卫**，或
  - 走**登记表**（`examples/m199_argtype/FALLBACK_ALLOW.tsv`，每条给「响亮在哪」的理由）。
  否则**判红**（源码里每个三元兜底站点都必须登记；表里每条也必须在源码中存在 ⇒ 双向防漂移）。

**(2) 解释轨必须按「函数面」口径守卫（[S10-b]）**：`ibuiltin.px` 的分支若把调用**转成方法调用**
（`args[0].m(...)`），位置错时的码与词条会与编译轨不同 ⇒ 必须**先**按 native 的同码同文守卫，
再执行（`replace` 本轮的修法即此）。

### 6.10.2 判据与工具（`examples/m199_argtype/`）

| 判据 | 内容 | 数字（M199 实测） |
|---|---|---|
| **[S10-a] 静态** | 全部**已注册** native 的逐参守卫声明 + 三元兜底站点 ⇄ 登记表双向对拍 | native 实现 **370** 个（注册 **346**）· 有逐参守卫 **256** 个函数 / **457** 个位置 · 三元兜底 **10** 站点（登记 7 条）· 未登记 0 · 表漂移 0 |
| **[S10-b] 动态** | **从声明自动生成**探针（全参类型正确、只第 P 位为毒值 `{}`）→ 合成**一个**驱动器 → **两次编译**覆盖全量 → 三轨对拍 `rc + R 码 + 消息体 + stdout` | 探针 **176** 条 / **116** 个函数（+ 合法侧 10 条）· **分叉 0** |

> **为什么必须合成单一驱动器**：一例一次 `build` 是 **136 例 × ~200s ≈ 7.5 小时** —— 不可行
> （M198 的 14 例已接近上限）。把全部用例放进**一个**程序的 `args()[1]` 分派里后，两次编译
> （VM/C）即可覆盖，随后每次执行 ~10ms ⇒ 「逐参类型面」从**抽样**变成**全量**。
> ⚠️ 副作用族（spawn/kill/网络/文件写/sqlite/ffi…）**不做动态**（只做静态判据）；
> 但**不得**用过宽的前缀把它们一刀切 —— 那会把 `exit`/`udp_open`/`tls_server`/`ws_heartbeat`
> 这类「守卫先于副作用」的函数（**恰恰是缺陷 237 的所在**）也排掉。

## 6.11 `extern def`（C-FFI 桥）名字的**全局发布**（M200 建立 · 缺陷 240）

|---|---|---|
| 解释轨 | `selfhost/iexpr.px` 遇未知名/FFI 名 → `i_builtin_ffi_call` → C 侧 `ffi_call` 的**双表**（ffi 注册表 → 全局 native 表） | 仍可用（兜底） |
| **编译轨（VM/C）** | 把 `extern def f(...)` 编译成 **GETG "f"** —— GETG **只查全局表** | `R1001 未定义变量: 'f'` |

**实现**：`px_ffi_publish_globals()`（`runtime/runtime_ffi.c`），在 `px_register_builtins()` 的
**建表窗口末尾**（`g_gc_frozen = 1` 期间，见 M170 缺陷 189）**遍历整表**逐条发布；调用点必须
**唯一**且位于 `g_gc_frozen = 0` 之前（窗口外发布的对象可能被 GC 误回收）。

**量化（M200 实测）**：`px_ffi_register` 名字 **92** 个 · 其中也走 `px_set_global` 的 **89** 个 ·
**仅 3 个只活在 FFI 表** = `zlib_crc32` / `zlib_compress` / `zlib_uncompress`
（⇒ 当时只有官方 `registry/zlib` 受影响，症状"专挑一个包"极难归因）。
第三方把这条记作 **PX-DEF-035**，但**方向记反了**（见 `docs/PX_DEF_TRIAGE.md` §8.2）。

**判据 [S11]**（`examples/m200_ffi_globals/sweep_ffi.py`）：注册名 ≥ 80（下限，防扫描器失效）·
发布函数定义存在且**遍历整表** · 发布调用点**唯一**且在 `px_register_builtins` 内、窗口之前 ·
打印 FFI-only 名清单（供人核）。
⚠️ 扫描器**取注册名要用"只去注释、保留字面量"的剥离器** —— 首版用连字面量一起抹的剥离器，
`px_ffi_register("zlib_crc32"` 变成 `px_ffi_register(""` ⇒ 名字数扫成 **0**，被"下限"判据当场抓住。

## 6.12 `bytes_to_int` 的**双模型**与 `bytes_to_dec`（M201 建立 · 缺陷 242 = 第三方 PX-DEF-031 + "静默 null"族）

### 6.12.1 病与判定

第三方写 mysql/pg 驱动时登记：`bytes_to_int(hex_to_bytes("ffffffffffffffff"), "little", false)`
返回 **-1**（应 18446744073709551615）—— **三轨一致但静默给错值**，且语言 `int` 是 64 位**有符号**，
装不下 u64 ⇒ 他们只能手写「32 位高低字长除法」（`mysql/stmt.px::my_u64_dec`）绕行。

**判定分两层（各自落地）**：

| 层 | 结论 | 依据 |
|---|---|---|
| **8 字节 unsigned > 2^63-1 ⇒ 保留回绕**（`ffffffffffffffff` ⇒ `-1`） | **设计如此**，**不是**缺陷 | 语言只有 int64；回绕 = Go `int64(uint64)` / Java `getLong()` / C 强制转换的**同款语义**，且是"读**原始位模式**"（float64 位型、消息字段）的**唯一可用形态**。实测官方 `msgpack`（float64 位型 + uint64）、`mysql`（DOUBLE 列）都依赖它 —— **改成报错会打破这两个库** |
| **更宽的精确值** ⇒ 缺一个一等公民 | **真缺口** ⇒ 新增 `bytes_to_dec` | 第三方自己也写"官方宜考虑 `bytes_to_uint64` 或以字符串/错误形式返回" |

### 6.12.2 `bytes_to_dec(b[, endian[, signed]]) → str`

- 整段字节走**十进制长除法**（不经 double ⇒ **无精度损失**），宽度 **1..16**（u64 / u128）；
  `signed=true` 按**补码**取负（输出带 `-`）。
- 实测（期望值由 bignum **独立**算得）：

  | 调用 | 结果 |
  |---|---|
  | `bytes_to_dec(hex("ffffffffffffffff"), "big", false)` | `18446744073709551615`（2^64-1） |
  | `bytes_to_dec(hex("0000000000000080"), "little", false)` | `9223372036854775808`（2^63） |
  | `bytes_to_dec(hex("ffffffffffffffff"), "big", true)` | `-1` |
  | `bytes_to_dec(hex("ffffffffffffffffffffffffffffffff"), "big", false)` | `340282366920938463463374607431768211455`（2^128-1） |

- **同族的"静默 null"收口**：`bytes_to_int` 长度越界（`<1` 或 `>8`）修前**静默返回 `null`** ——
  与 M199 修掉的 `bytes_get` 越界 null **同族**（null 流到下游只报"无法比较 null 与 int"，
  **指不到越界点**）⇒ 改 **`R1003`**，消息里指明"更宽的整数用 `bytes_to_dec`"：
  `R1003: bytes_to_int 需要 1..8 字节，实际是 9（更宽的整数用 bytes_to_dec）`。
  `bytes_to_dec` 越界同理（`R1003: bytes_to_dec 需要 1..16 字节，实际是 17`）。

### 6.12.3 判据（`examples/m201_bytes_dec/`）

三层 + 3 道负控（各自独立判红）：正例 **23 项 × 三轨逐字节一致**（期望值 bignum 独立算得）·
拒绝侧 **4 例 × 三轨**（rc≠0 + 同码 + 同文案 + 前置标记）· 负控
**A** 删注册 ⇒ 三轨 `R1001` · **B** 长度守卫改回 `null` ⇒ **仅**越界例红（正例仍绿 = 独立牙）·
**C** 宽度上限 16→8 ⇒ 正例红且**失败原因读得到**（`实际是 16`）。

## 6.13 「能力面」必须是**可查询的事实** + 解释器件必须**全能力**（M201 建立 · 缺陷 241 = PX-DEF-035 复现）

### 6.13.1 实测取证（不是推理）

第三方登记 **PX-DEF-035**：官方 **aarch64 引导包**里 `import "c/zlib"` + `extern def zlib_*`
编译轨全通、解释轨 `Err(ffi_call: 未注册函数: zlib_compress)`。
M200 我在 **x86_64 仓库内态**上复核得出"他们方向记反了"—— **那个结论错了**。
本轮把**已发布**的 m197 / m200 aarch64 包**下载解包逐件复核**：

| 件 | `zlib_*` 名字数 |
|---|---|
| `bootstrap/pxc` | **19** |
| `bootstrap/pxi` | **0** |

且族级差异不止 zlib：**aes / rsa / ed25519 / sqlite / xml / zip / ws 整族都缺**。

**根因**：发布链用 `tools/px build <interp.px>`（**按引用集自动裁剪**）现编解释器；解释器是
**泛化分派**（native 名运行期按字符串查表）⇒ 裁剪器"看不见"这些名字 ⇒ 把整族模块裁掉。
仓库内 x86_64 入库件**不受影响**（`devbuild.sh` / `rebake_bin.sh` 链的是**全量** runtime 对象）
⇒ 缺陷**只在发布链**、只在非 x86_64 包上被第三方看见；而 CI 只问"能不能跑 hello"⇒ 一直绿。

### 6.13.2 对策①：`native_symbols()` 查询原语

`native_symbols() → [str]`：本构建里**可作为全局调用的 native 名**（排序去重）。
数据源 = `px_set_global(name, v)` 中 `v` 为 `PX_NATIVE` 的登记（只存指针，指向全局表已
`xstrdup` 的名字 ⇒ 可在"全局表写锁 + GC 冻结"窗口内安全登记，M170 缺陷 189 的约束不变）。
⇒ "这个构建有没有某能力"从**靠猜**变成**可查询**（第三方登记里点名要的原语）。

### 6.13.3 对策②：构建口径收敛到**一处** + 泛化分派件 `--full`

- **口径**：**泛化分派件（把用户程序当数据来解释/执行）必须 `--full`** —— 目前只有 `pxi`；
  其余件按引用集自动裁剪（那是**特性**：二进制更小，它们的输入不是用户程序）。
- **唯一入口**：`selfhost/build_native_tools.sh`（11 件 + `pxc` 由 `native_bootstrap.sh` 产出）。
  原先 `ci.yml` 与 `release.yml` **各写一遍** 12 件循环 —— 那正是漂移的温床。
- 两个发布/CI 路径都改为调用该脚本，并在装好件之后跑能力面门（失败走 `::error::` 注解 ——
  本仓 job 日志外部不可读，只有注解能被看见）。

### 6.13.4 判据（`examples/m201_interp_ffi/`）

- **期望集从源码派生**：`runtime/*.c` 的 `px_set_global("X", px_native(` ∪ `px_ffi_register("X"`；
  按本架构能力过滤（`--print-plan` 的 `no_quic` ⇒ 剔除 `quic_*`/`h3_*`，**合法缺席不算缺**）；
  自证：规模 ≥ 下限（默认 300）+ **14 个家族代表逐个在场**（防判据锚点静默失效）。
- **被测件实跑** `<interp> dump_symbols.px` ⇒ 报告的集合必须**包含**整个期望集（缺失逐条打印）。
- **动态真调用**：`zlib_crc32` / `zlib_compress`↔`zlib_uncompress` / `bytes_to_hex`↔`hex_to_bytes`
  在解释轨与编译轨**逐字节一致**（名字存在 ≠ 已注册 ≠ 可调用 —— M200 就是栽在最后一步）。
- **负控**：**A** 用**真被裁过**的产物（`--no-zlib`）⇒ 判红并**指名** `zlib_compress`；
  **B** 空输出探针 ⇒ 必红（防"空集 ⊇ 任意集"的假绿）；**C/D** 自调用（抬下限 / 抽锚点）⇒ 必红。

### 6.14 M203（第 82 轮 · 缺陷 243-a/b/c）：**「此类型不支持X / 不可迭代」族的三轨同码同文**

「这一族四个站点，M191 只收口了『切片』一个」——本条把其余三个补齐：

| 站点 | 修前（解释轨 ⇄ 编译两轨） | 修后（唯一） |
|---|---|---|
| 切片 | `此类型不支持切片: <t>` ⇄ `此类型不支持切片: <t>` ✅ M191 | `R1002 此类型不支持切片: <t>` |
| **索引** | `此类型不支持索引`（缺类型）⇄ `此类型不支持索引: <t>` | `R1002 此类型不支持索引: <t>` |
| **迭代** | `此类型不可迭代`（缺类型）⇄ **`len 不支持类型 <t>`** | `R1002 此类型不可迭代: <t>` |
| **索引赋值** | `索引赋值目标不支持`（词条全不同）⇄ `此类型不支持索引赋值: <t>` | `R1002 此类型不支持索引赋值: <t>` |

**为什么「迭代」自成一码而不并进「索引」**：迭代与索引在 M164 已明确分开
（`px_iter_at` ⇄ `px_index`）——用索引的词条描述迭代正是 M164 要根治的混淆。

**实现（单一真相）**：runtime 新增 `int px_iter_prepare(LXValue v)` —— 可迭代
（`str`/`bytes`/`list`/`dict`/`tuple`/生成器）⇒ 返回长度；否则响亮报上面的词条。
- C 轨直接发射 `px_iter_prepare(...)`（for 循环 + 推导式**两条**发射点）；
- VM 轨经**内部全局** `__iter_len`（`__` 前缀 ⇒ **不进公开 native 名册/索引**）调用同一个函数
  —— 修前它借 `px_len`，于是把 `for x in 1` 报成 `len 不支持类型 int`：消息指向用户**从未写过**的 `len`。

**诊断纪律**：错误消息里出现的名字，必须是用户**在源码里写过**的东西（否则无从下手）。
