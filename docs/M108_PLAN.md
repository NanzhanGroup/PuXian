## 2. S1 详设（Issue 31，根因已定位）

### 2.1 缺陷

`h_exchange` 的 keep-alive 判定**只认响应头有无 `Connection: close`，不判 HTTP 协议版本**：

- HTTP/1.0 上游（无 `Connection` 头 + 有 `Content-Length`，发完即关）→ 被误判可复用 → **死连接放回池**；
- 第二次请求取到死连接 → 失败返回 Err，且 `retries` **不覆盖"已取池连接"路径** → 不自动新建重连；
- ⇒ **奇偶失败**（第 1/3/5 次成功、第 2/4/6 次失败）。

### 2.2 修法

1. **判定补全**：`HTTP/1.0` 无 `Connection: keep-alive` ⇒ **默认不可复用**（按协议版本 + 头共同判定）；`HTTP/1.1` 维持"无 `Connection: close` 即可复用"。
2. **取池失败自愈**：从池中取出连接后、**在写请求行之前**失败 ⇒ **新建连接重试一次**；若已写请求行（可能已产生副作用）**不重发**（避免 POST 重复提交）。

### 2.3 复现/验收（已在 ISSUE 中给出）

| 项 | 期望 |
|---|---|
| 模拟 HTTP/1.0 上游连续 3 次 `http_request` | **r1/r2/r3 全 OK**（改前 r2 ERR）——奇偶模式归零 |
| 真实 Mahesvara `proxy_forward` 连续请求 | 无失败、进程不崩（业务层止血可保留，非依赖） |
| 回归 | 双自举逐字节 + `vm_ab` 38P/0GAP/0F + `diffcheck --all` rc=0 + 既有 suite 全绿 |

## 4. 语义红线

1. **幂等优先**：取池失败重试**只在未写请求行时**进行；POST/有副作用请求不得重复提交。
2. **HTTP/1.1 行为不回退**：判定补全只影响"HTTP/1.0 无 keep-alive 头"这一分支；HTTP/1.1 复用语义严格不变。
3. **服务端兼容**：`http_serve` 与 `http_serve_unix` 共享 `http_conn_worker` ⇒ 改动**两侧同时**生效，须双冒烟。
4. **线程池模型不退化**：不得为解决 32 而引入"每连接一线程"等偏离 M88-A 模型的改动。
5. 跨轨一致：C 轨 / VM 轨共用 runtime ⇒ 双侧生效。
