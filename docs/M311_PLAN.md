# M311_PLAN · 门超时口径入仓（A）→ 发布物校验清单统一 + 真模型端到端（C）→ 全量门工作量压缩（B）

> **顺序即优先级**：A（小）→ C（小-中）→ B（中）。每项收口后再进下一项，不并行开三摊。

> **本轮主题一句话**：M310 暴露的三条欠账，共同点是「**知识在仓外 / 校验面不全 / 重复劳动**」——
> A 把「每门该给多少时间」这份知识从**宿主脚本**搬进**注册源**；
> C 把「发布物完整性」从**人工核对**变成**判据**，并让**真模型**进判据；
> B 把「4 路分片重复建产物」这笔**重复劳动**先量化再压缩。

## 一、A · 门超时口径入仓（优先，直接来自 M310 的那次红）

### 1.1 事实（全部实测，不猜）

| 事实 | 数据 | 来源 |
|---|---|---|
| `upstream_tests` 真实耗时（空闲） | **963s** | 2026-10-18 00:39–00:55 单跑（`/tmp/m116_gates.times.tsv`） |
| 同一门在 4 路分片下 | **898s / 902s** | `shard-20261018-010156` / `shard-20261017-103127` 的 `shardN.times.tsv` |
| 串行档**默认上限** | **900s** | `run_gates.sh: GATE_TIMEOUT_DEFAULT=900` |
| 后果 | D2 段2 该门 **rc=124**（`FAIL 902s`）⇒ 全量门唯一红 | `/tmp/m310/d2b_times.tsv` |
| 分片档为什么没撞 | 宿主侧 `shard_run.sh` 硬写了 `GATE_TIMEOUT_upstream_tests=1800`（**两处**） | `/data/gatevm/shard_run.sh:252,273` |

⭐ **病灶不是「忘了加超时」，而是这份知识在仓外**：同一件事在仓库里**没有任何记录**，
靠宿主脚本两行硬编码兜着 ⇒ 任何人跑**串行全量门**（权威档！`gate_verdict.sh` 裁决的就是它）必撞。
这与 M243 修的「三份门清单」是**同一类**：**第二份真相**。

### 1.2 交付

| # | 物 | 判据 |
|---|---|---|
| **A1** | `gates.registry.sh` 支持 `gate_timeout <门名> <秒>`（**声明与 `run` 行同源**）；为 `upstream_tests` 声明 **1800** | 声明必须写在同名 `run` 行**之前**（sourced 线性求值） |
| **A2** | `run_gates.sh` 解析顺序：`env GATE_TIMEOUT_<门名>` > **注册源声明** > `GATE_TIMEOUT_DEFAULT` | 三层各有自证；`--list` 仍**零副作用** |
| **A3** | **配额告警**：某门用掉 ≥80% 上限 ⇒ 运行期 `⚠️ 配额告警` + 汇总点名 | 不改变判据（不因此判红）；目的是「下一个顶穿的门在**当次**就被看见」 |
| **A4** | 守卫 `selfhost/check_gate_timeouts.sh`：① 声明的门必须存在（悬空 ⇒ 红）② **实测最大耗时 ≥80% 生效上限 ⇒ 红**（含未声明、用默认档的门）③ 声明档必须给出 **≥1.5×** 裕度（否则「声明了也不够」）④ 基线缺失 ⇒ ℹ️（不装作有数据） | 自带自证 ≥5 条 + 规模锚点；基线来源逐行标注 |
| **A5** | 基线 `selfhost/gate_time_baseline.tsv`：**216 门串行实测**（D2 两段合并，去重），带来源列 | 生成脚本 `--from <tsv>...`；不手抄 |
| **A6** | 宿主侧两行硬编码**删除**（回归单一事实源） | 删前确认分片 worktree 恒取自 HEAD（`shard_run.sh:207-215`）⇒ 注册源一定在 |
| **A7** | 文档 `docs/GATE_TIMEOUTS.md`（口径 / 三层优先级 / 为什么是 1800 / 刷新基线的流程）+ CHANGELOG | — |

### 1.3 红线

- **判据不放松**：不缩短任何门的实际工作量、不加「超时自动重试」、不把失败改成跳过。
  1800 只是**资源上限**（一个真挂住的门仍会被 1800 拦下）。
- **不手改基线**：基线由 `--from` 生成；人工只允许改 `来源` 说明。
- 宿主脚本的改动**单独**做，且改后跑一次 `--dry` 确认门清单不变。

## 二、C · 发布物校验清单统一 + 真模型端到端

### 2.1 事实

| 事实 | 数据 |
|---|---|
| `sha256sums.txt` 只含**主包** | `tools/make_release.sh:243`（`sha256sum "$(basename "$PKG")"`） |
| aarch64 引导包只有**同名 sidecar** `.sha256` | `release.yml:322` |
| 后果 | 下载者用「一个清单核全部资产」时**核不到 aarch64 包**；两套口径（sums / sidecar）并存 |
| 真模型在盘 | `/data/app/ws/models/embed/model.onnx` **102 MB · int8 量化 bge**（`onnx.quantize`） |
| PuXian 跑它 | **1177 节点 / 363 initializer / 3 输入 / 1 输出**；`onnx_run` **ok=true**，输出 `last_hidden_state [1,4,768]`，`tools/px run` 全程 **3.6s** |
| 独立参考可用 | `/opt/fw/onnxruntime/capi/libonnxruntime.so.1.19.2`（**真 onnxruntime**，可做跨实现数值对拍） |

⭐ M306 补齐 `DequantizeLinear/QuantizeLinear/DynamicQuantizeLinear/MatMulInteger` 之后，
**生产在用的那个 int8 模型第一次能端到端跑**（by_op 实测：Add 172 / Cast 73 / MatMulInteger 72 / DynamicQuantizeLinear 48 / …）。

### 2.2 交付

| # | 物 | 判据 |
|---|---|---|
| **C1** | 发布物校验清单**统一**：`sha256sums.txt` 覆盖**全部**发布资产（主包 + aarch64 包）；sidecar 保留（向后兼容） | 发布链断言：资产集合 ⇄ 清单集合 **双向相等** |
| **C2** | 守卫：`release.yml` 在打包后、上传前**核对清单完整性**（缺一 ⇒ 红，指名缺哪个） | 失败信息指名文件，不许「exit code 1」 |
| **C3** | 门 `examples/m311_real_model/`：真模型端到端 × **onnxruntime 独立参考**数值对拍（固定 input_ids/mask/type_ids，seq=4） | ① `ok=true` ② 输出形状/长度 ③ **max abs err ≤ 容差**（容差由两实现差异实测后**写明**）④ 两次跑**逐字节一致**（确定性）⑤ 负控：改一个 token ⇒ 输出必须变 |
| **C4** | 覆盖边界如实登记：只验 seq=4 单批；不验 fp32 模型；onnxruntime 版本钉住 1.19.2 | — |

### 2.3 风险

- onnxruntime C API 需要编译期头文件；若头文件缺失 ⇒ 用 `dlopen` + 手写最小函数指针表（同 Go 侧 `embed_onnx` 的做法），
  **不引入 pip / 不联网**。**先探。**
- 若两实现差异超预期 ⇒ **先定性**（是否 int8 反量化路径差异），**不许直接放大容差**。
