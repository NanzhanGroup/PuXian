## 1. S0 复现定标（已完成）

### 1.1 行级核对（读码，非推测）

| 位置 | 形态 |
|---|---|
| `selfhost/ival.px:249-261` `i_index()` 字符串分支 | 每次 `s[i]` **物化 n 元字符表**（`while ci < len(v): chars.append(v[ci])`）⇒ O(n)/次 |
| `selfhost/ival.px:354-367` `i_slice()` 字符串分支 | **完全相同的物化** + 输出侧 `out += chars[...]` **二次方拼接** |

**全仓 grep 确认只有这两处**（`grep -n "chars.append\|chars = \[\]" selfhost/*.px` → 仅 249/252 + 354/357）。

### 1.2 为何 `v[ci]` 不致命（决定修法）

`ival.px` 自身是**编译产物**，其中 `v[ci]` 走**原生 `px_index`**（M106 偏移表 O(1)），**不会递归回 `i_index`**（后者只服务被解释的用户 AST，入口 `selfhost/iexpr.px:92`）。⇒ **O(n) 的唯一来源就是那张表**。

### 1.3 语义 golden（**新旧逐字节对拍用**）

- `sem.px`：**55 条**有效用例（空串/单字符/纯 ASCII/多字节混排/负索引/负 step/clamp/链式/大串），含**双向遍历一致性**（正序逐位 vs 反序逐位）与**切片-拼接交叉验证**（`s[2:7] == s[2]+…+s[6]`）
- `err/e1..e6.px`：**6 条**错误路径（越界/负越界/空串取 0/float 索引/字符串索引/多字节越界），逐条比 **stdout + stderr + 退出码**
  - 实测：错误信息走 **stdout**（不是 stderr），`rc=1`，`[R1003] 索引越界` / `[R1002] 索引必须是整数`
  - 注意 `i_as_index` **已先**对 `i>=n` 报 `R1003 索引越界` ⇒ 字符串分支里那句 `R1003 字符串索引越界` **不可达**（§3.1）

### 1.4 性能基线（`taskset -c 3` 单核，同一 `bootstrap/pxi`）

| 用例 | 基线 | 说明 |
|---|---|---|
| `IDX n=4096` | **5 603 ms** | 与立项书 5 401 ms 同档 |
| `IDX n=16384` | 见 §2 实测表 | O(n²) ⇒ 预期 ≈16× |
| `SLICE-A`（200 次 `[0:200]`，n=16384） | 见 §2 | 物化主导 |
| `SLICE-B`（3 次 `[0:]`，n=16384） | 见 §2 | `out +=` 拼接主导 |

> ⚠️ **`px run <script> <extra>` 不接受额外位置参数**（位置参数一律被当作脚本路径），故基准用**字面量内嵌**字符串；`now_ms()` 计时。

## 2. S1 + S2 改动（同一次提交）

### 2.1 S1 · `i_index` 字符串分支

```puxian
# 改后
if t == "string":
    let n = len(v)
    let r = i_as_index(idx, n, pos)
    if r.is_err():
        return Err(r.err())
    var i = r.unwrap()
    return Ok(v[i])
```

**等价性证明**（三条，逐条可核）：
1. `chars[j] ≡ v[j]` ∀`j ∈ [0, n)` —— `chars` 由 `append(v[ci])` 逐位构造，`ci ∈ [0, len(v))`；
2. `len(chars) ≡ len(v)` —— 循环体恰好执行 `len(v)` 次 ⇒ 传入 `i_as_index` 的 `n` 不变；
3. 被删的 `if i >= n: return Err(i_r1003("字符串索引越界", pos))` **不可达** —— `i_as_index` 已在 `i >= n`（及负索引下界）先行返回 `Err(R1003 索引越界)`；`i` 到此处必满足 `0 ≤ i < n`，故 `v[i]` 必安全。

### 2.2 S2 · `i_slice` 字符串分支

```puxian
# 改后
if t == "string":
    let r = i_slice_indices(start, end, step, len(v))
    if not r["ok"]:
        return Err(i_r1002(r["err"], pos))
    let idxs = r["idxs"]
    let parts = []
    var ii = 0
    while ii < len(idxs):
        parts.append(v[idxs[ii]])
        ii += 1
    return Ok(join("", parts))
```

**等价性证明**：
1. `i_slice_indices` 的第 4 参由 `len(chars)` 改为 `len(v)`，二者恒等（§2.1-2）⇒ 索引表逐项相同；
2. 取到的字符序列逐项相同（§2.1-1）⇒ 拼接结果同串；
3. `join("", parts)` 与逐次 `out +=` 对**同一序列**结果相同；`parts` 为空时 `join("", []) == ""`（**已实测**：`empty_eq=true`）；
4. 新增 `idxs` 局部量仅为避免重复求值 `r["idxs"]`，无行为影响。

### 2.3 未纳入本轮（登记在案）

| 项 | 原因 |
|---|---|
| `bytes(s)` 视图兜底 | `bytes` **不支持索引**（`R1002 此类型不支持索引`）⇒ 不构成业务侧兜底（立项书 §9） |
| 统一 pxi 与 runtime 的字符串表示 | 里程碑级（立项书 §5-6 明确不做） |
| `i_slice_indices` 自身的 `idxs.append` 累积 | 该表长度 = 结果长度（不是 n）⇒ 属**线性**成本；若结果巨大可后续「不建表直拼」，本轮不动（保持等价性最易证） |

## 6. 实测结果（2026-09-12 · dongyue · `taskset -c 3`）

### 6.1 语义等价（S1+S2 改后 vs 改前）

| 项 | 结果 |
|---|---|
| `sem.px` 55 用例 | **逐字节一致**（56 行 · md5 `69adae8d9589b27cfb06377419df8c1c` 前后同值） |
| `err/e1..e6` 6 条错误路径 | **stdout + stderr + rc 全一致**（`R1003 索引越界` / `R1002 索引必须是整数`） |

### 6.2 性能

**`s[i]` 循环**

| n | 改前 | 改后 | 加速 | 改后每迭代 |
|---|---|---|---|---|
| 4 096 | 5 603 ms | **395 ms** | 14.2× | 96 µs |
| 16 384 | 94 781 ms | **1 357 ms** | 69.8× | 83 µs |
| 65 536 | （O(n²) 外推 ≈27 min，未实跑） | **5 956 ms** | ≈270× | 91 µs |

线性度：4096→16384 = **3.43×**（理论 4×）· 16384→65536 = **4.39×**（改前同两点 16.9× = O(n²)）

**对照组 `len(s)`（同一二进制）**：4096 档 365 ms（89 µs/迭代）· 16384 档 1 602 ms（98 µs/迭代）

⇒ **改后 `s[i]` 每迭代成本 == `len(s)` 每迭代成本（83~98 µs）**：字符串下标**不再特殊**，
残余 = 解释器**逐节点求值的固有开销**（tree-walking），**与串长无关**。

**切片**

| 项 | n | 改前 | 改后 | 加速 |
|---|---|---|---|---|
| SLICE-A（200×`[0:200]`） | 4 096 / 16 384 / 65 536 | 339 / 1 158 / — ms | **33 / 61 / 305 ms** | 10.3× / 19.0× / — |
| SLICE-B（3×`[0:]`） | 4 096 / 16 384 / 65 536 | 50 / 213 / — ms | **3 / 30 / 272 ms** | 16.7× / 7.1× / — |

### 6.3 ⚠️ 立项书 §6 的性能目标**设错了**（更正）

原写「`n=4096` → ≤60 ms（≈90–100×）· `n=16384` → ≤250 ms」。实测 **395 ms / 1 357 ms**，看似"未达标"。
**错在目标本身**：那组数字隐含"残余 ≈15 µs/迭代"，而 tree-walking 的实际固定成本是 **≈96 µs/迭代**（与 `len(s)` 同档，见 §6.2 对照）。
**判据应改为**：① 斜率随 n **线性**（已证 3.43× / 4.39×）；② **`s[i]` 每迭代成本与 `len(s)` 同档**（已证 83~98 µs vs 89~98 µs）。
这两条才是"O(n²) 已消除"的可判据表述；绝对毫秒数取决于解释器整体速度（另一件事）。
与编译轨同循环的 ≈100×（4 ms @4096）是"解释 vs native"的固有差距，不在本 Issue 范围。

## 4. 语义红线（照立项书 §5，逐条自查）

1. `px run` 与 `px build` 可观测行为**逐字节一致**（性能可不同，行为不可）
2. **rune 语义不得回退为字节**（多字节下标/切片；33-A 教训）
3. 越界/负索引**错误码与消息不变**（`R1003 索引越界`；`R1003 字符串索引越界` 改后仍不可达）
4. 全档等价：空串 / 单字符 / 纯 ASCII / 多字节混排 / 负索引 / `step` 为负
5. 不改 pxi 对外 ABI；`pxi` 与 `pxi_vm` **同源重建同时更新**
6. **不做**「统一 pxi 与 runtime 字符串表示」
