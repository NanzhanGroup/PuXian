**已实测事实（M309 阶段 B2 复测 · 非推断）**：

| 门 | A' quiet 档 | 空闲机单跑 ×3 | 门时长 | 移交时已知形态 |
|---|---|---|---|---|
| `m183_gc_root_handover` | ❌ 偶发 | ✅ rc=0 ×3（37/39/41s） | 51s | 判据② `runs_ok 10`（`PX_GC_STRESS=1` ×10 连跑，须每次 `HANDOVER OK`）· 实测有 1/10 量级 `HANDOVER FAIL` |

- M309 结论：**与并行编排无关**（分片早已结束、机器已空仍偶发）⇒ 归因「GC 压力门的时序边缘」，

  （先例：M274 缺陷 480「一个会偶发判红的门，等于没有门」）。

**目标**：
1. **量化**：给出门级**复现率**（n/N，不是轶事），并测**触发条件**（开关矩阵 / 连跑次数 / 机器负载）。
2. **定性**：能定位则定位（`PX_GC_TRACE` / `LIVECHK` / `UAFDET` 三检测器武装 + core 栈），
   给出**「产品缺陷 / 判据自身 / 环境边缘」三选一**的判定与证据。
3. **处置**：按判定给出**显式**出口 —— 修（并加判据）/ 改判据（须**等强**且带反向判据）/ 如实归档。

**⚠️ 第一子步 = 量化复现率，不是改代码**：
先例 M289/M290（两轮否证 —— 那次「修复」被证明是**空操作**、表观效果来自调度扰动）·
M207 的 `SLOW.tsv`（先量后定，把「慢」与「坏」分开）。**量化不成立同样是交付物**。

**非目标（硬约束）**：
1. **不改任何门的判据强度** —— 不许把 ×10 连跑改 ×3、不许加「失败重试一次」、不许把偶发红静默吞掉。
   （红线出处：M228「门的语义不能被一个默认值/容错偷偷换掉」· M230「改行为 ⇒ 期望值移位 + 加反向判据」。）
2. **不改 `runtime/*.c` 的 GC 语义**，除非 A 阶段**证到**产品缺陷并定位到行。
3. **不重开已否证的方向**（M289 主线程注册 / M290 帧槽窗口）—— 若要重开，须给出**新的**判据与理由。

### 5.4 A5 定性：**B-1 产品缺陷**（附机制与定位）

**机制（代码可复核）**：

1. `http_pend_take(fd,…)` 把 `req/resp` **从挂起表摘掉**（表本身是 GC 根面）⇒ 摘除瞬间两者只剩 C 局部。
2. `runtime.c:19771`：`px_root_push_keep(fr);   PX_KEEP(fs);` —— `px_root_push_keep` 的出口
   （`gc_unblock_stop → gc_pause_if_requested`，M110-S2）是**协作式安全点**：此刻 **`fr` 已在根栈、`fs` 尚未入栈**。
3. 并发 GC 恰在此窗口暂停本 worker：快照 `ti->root_n` 只含 `fr` ⇒ **`resp` 无根 ⇒ 本轮 sweep 回收**。
   恢复后 `PX_KEEP(fs)` 压入的是**死指针**；`http_send_resp` 读 `resp["file"]` ⇒ LIVECHK 响亮。
4. 为什么 INLINE 不犯：同线程内联 GC **不会**在该窗口暂停本线程 ⇒ D/E/F 0/300。
5. 为什么 TRACE 0 命中：`gc_trace_freed_registered()` 判据是「回收时对象**仍**在根栈」，
   而本病灶是「回收时 `fs` **尚未**在根栈」⇒ 结构上不命中（FINDINGS §四的预判被证实）。
6. `GC_DEBUG` 现场（第 14 轮复现）：41 轮 collect 全为 `跳过 0`（**不是** 5s 兜底降级）；
   受害者线程槽 `paused=0 epoch=57`（全局 `epoch=58`）+ 两条 `[stop-expired]`
   ⇒ 该 worker 在那一轮处于软屏蔽区、信号排队到轮末才投递，**未参与该轮根栈快照**。

**B-1 出口（B 阶段执行，本轮不改码）**：

- 修法：新增「双值原子登记」`px_root_push_keep2(a,b)`（一个临界区内登记两值），
  `runtime.c:19771` 改为 `px_root_push_keep2(fr, fs);`（等价方案：把挂起表摘除推迟到两值登记之后）。
- **反向判据（不放松）**：修复后 4 路竞争下 ① G 格 `STRESS+LIVECHK` ×100 必须 **0 LIVECHK**；
  ② m183 门 `--neg-skip` ×10 **全绿**；③ 不得引入静默重试 / 降 `×10`。

### 5.6 B-1 修复 + 反向判据（2026-10-17 10:05–10:11，已落地）

**改动（`runtime/runtime.c` 2 处，最小闭包）**：

1. 新增 `px_root_push_keep2(a,b)`：两值在**同一个暂停屏蔽临界区**内入根栈（一次 marks 条目，配一次 `px_root_pop`）；

## 七、同形状站点排查（只登记，不改 —— 红线「先证再改」）

甲1 修复的判据是「**从根面消失到重新入栈之间不得存在安全点**」。按此判据静态扫全仓
`px_root_push_keep(a); PX_KEEP(b);` 两段式（两值都刚从表/栈移交、都只被 C 局部持有），

| 站点点位 | 上下文 | 判定 |
|---|---|---|

**为什么本轮不改**：
1. 该路径**没有复现证据**（pxserve 需多线程 + 并发 GC 压力才能触发；现有 m208/pxserve 门未观测到）；
