# HTTP/1.1 头部**字段语法**契约（M434 · 缺陷 897 / 898 / 899）

> 本文件是「一行头部字段算不算合法」的唯一口径。
> 门：`selfhost/check_header_syntax.sh`（registry 名 `m434_header_syntax`）。
> 姊妹文件：`docs/HTTP_REQUEST_FRAMING.md`（管「体到哪儿结束」，M432）。

## 1 为什么有这份口径（修前实测，px_serve，2026-11-22 19:5x）

13 条判据里 **10 条不符契约**，且失败方式**全是静默**：

| 请求 | 修前 | 说明 |
|---|---|---|
| `Content-Length : 5`（冒号前空格） | **200，体被静默丢弃** | 字段名成为 `"Content-Length "` ⇒ 认不出来 ⇒ 体当空 |
| 同上，且体分片到达 | **200 × 2**（体被当成下一条请求执行） | 与前置代理的消息边界分歧 = 请求走私入口 |
| `Content-Length\t: 5`（制表） | 200，体丢 | 同上 |
| `Content Length: 5`（名内空格） | 200，体丢 | 同上 |
| `X@Y: 1`（非 token 字符） | 200，静默接受 | 各家中间件归一化不一致的入口 |
| `GARBAGE`（无冒号） | 200，整行静默丢弃 | 既不拒也不报 |
| `: value`（空字段名） | 200，静默丢弃 | 同上 |
| obs-fold 续行（下一行以 SP/HTAB 开头） | 200，续行静默丢弃 | RFC 9112 §5.2 要求拒（或替换 SP） |
| `Host: a` + `Host: b` | 200，**last-win 静默覆盖** | Host 注入面（缓存投毒 / 链接投毒） |
| `Host: a b` | 200，照收 | Host 值未校验 |

**共同病灶**：字段行只找**第一个冒号**，名字/值/重复都不校验；失败方式是「静默丢弃」或「静默覆盖」，
调用方（handler）看到的是一份**少了字段的请求**，且没有任何信号。

**为什么这是安全面**：字段名在冒号前带空白，是各家代理与源站之间**最常见的一类归一化分歧**
（多数代理会 trim）。分歧落在 `Content-Length` 上就直接变成请求边界分歧：
前置代理按 `CL=43` 把后继字节当体，本服务端按「无 CL」把同一批字节当**下一条请求**执行
⇒ 经典请求走私（RFC 9112 §6.4）。门的 H17 就是这条端到端判据。

## 2 口径（服务端最小集合，宁拒不含糊）

| 情形 | 处置 |
|---|---|
| 字段名不是 **tchar 串**（RFC 9110 §5.6.2）：空名 / 含空格 / 含制表 / 含其它分隔符 | **400** |
| 冒号前有 OWS（`Content-Length :`） | **400**（由上一条自然覆盖 —— 空格/制表不是 tchar） |
| 非空字段行**没有冒号** | **400** |
| 以 SP / HTAB 开头的行（obs-fold 续行） | **400** |
| 字段值含 CTL（裸 CR / 裸 LF / NUL / 其它 0x00–0x1F、0x7F） | **400** |
| 字段值含 HTAB 或 obs-text（0x80–0xFF） | 接受（合法值，不许误判） |
| `Host` 出现**多于一次** | **400**（RFC 9112 §3.2） |
| `Host` 值空 / 含空白 / 含 `,` `/` `\` `@` | **400** |
| `Host` 带端口、IPv6 字面量（`[::1]:8080`） | 接受 |

实现（`runtime/runtime.c`，两个服务端 worker **共用一份**判定）：

- `px_hdr_tchar` / `px_hdr_name_ok` / `px_hdr_value_ok` / `px_host_value_ok`
- 行级判定内联在两个 worker 的头循环里（obs-fold / 无冒号 / Host 计数），
  共同调用上面三个纯函数 —— 与 M432 的 `px_framing_feed` / `px_framing_resolve` 并列。

任何拒绝都沿用 M432 的口径：`Connection: close` + **先 drain 再关**（缺陷 892 的教训）。

## 3 缺陷 898：负控把「服务死了」当成「判据失效」（判据自身的坑）

第一版负控只摘了三个字段判据，**没有摘行级的两条**，结果同一批非法头仍被 400 ⇒ 负控不成立。
修好之后又踩到第二个坑：把 `if (!colon)` 也摘掉，`*colon = 0` 对 NULL 解引用 ⇒ **负控服务当场段错误**，
探针拿到的是全 `NA`，而「不是 400」在断言里等于「放行」⇒ **负控假绿**。

修法（两道）：
1. 负控**只摘字段级三条 + obs-fold 一条**；`if (!colon)` 保留（它是安全底线，摘了会崩）。
2. N1 增加**前提自证**：负控服务必须存活（`kill -0`）且 `H0 == 200`，否则 N1 直接判失败、
   并打印 `srv.log` 尾 8 行。与 M425/M427/M430 同族：判据自己的假绿比产品缺陷更该先修。

## 4 缺陷 899：门被 SIGTERM 打断会把源码留在「判据摘除」态

负控要就地改 `runtime/runtime.c` 再回滚。第一版只挂 `trap cleanup EXIT`，
一次工具层超时把门杀掉 ⇒ **EXIT 不执行** ⇒ 工作树里留下打伤的 `runtime.c`
（实测：`M434 N1：故意摘除` 标记还在，`git status` 显示 runtime.c 已改）。
修法：`trap 'cleanup; exit 130' INT TERM HUP`（信号也进清理，宁可重复清理一次）。
M432 的同款门有同样的问题，本轮一并加固了自己的副本。

## 5 覆盖边界（如实登记）

- ✅ 覆盖：`px_serve`（`px_conn_worker`）与 `http_serve` / `http_serve_unix`（`http_conn_worker`）的**请求头**。
- ⚠️ **未**覆盖：客户端读**响应**时的头部语法（`px_http_request` / `px_stream`）—— 另轮。
- ⚠️ **未**做：HTTP/1.1 请求**缺少 Host** 时回 400（RFC 9112 §3.2 的强制项）。
  现状是不要求 Host（HTTP/1.0 兼容考虑）；加这条会影响既有内部探针与脚本，需单独立项。
- ⚠️ **未**做：字段行长度上限（当前单行截断在 4095 字节；超长行会走「无冒号/名字非法」被判 400，
  但**不是**按「行长超限」的语义判定）。
- ⚠️ 请求**行**（method / target / version）的语法校验不在本口径内。
