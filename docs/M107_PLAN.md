## 0. 为什么这四条要合批

M104→M105→M106 已把「值层 / 名解析 / 字符串下标」修到可用。剩下影响**所有 `while` 逐元素循环**的成本，全部是"每次迭代固定付一笔"的常数项：

| Issue | 每迭代固定代价（实测） | 典型受害者 |
|---|---|---|
| 35 全局名直呼 | ~~1.4 µs/次~~ → **S0 实测 40~50 ns/次**（原 13× 已由 M105-S2 消解，残余 1.9×） | 逐字节扫描、逐字符解析、热循环调 native/def |
| 34 `{n,}` 命中共鸣 | **≈162 µs/字节**（64KB 10598ms；固定 `{20}`=0ms） | 正则/密钥扫描/大文本 |
| 内存路径 | **mmap 59,361 + munmap 24,245**（99.9% 单页）；sys 占墙钟 **24%** | 所有程序的基础成本 |

**共同点**：都不是算法错，是"原语层把 O(1) 做成了常数巨大的 O(n)"。合批可共用同一套量化/回归门，一次把"逐元素循环"类代码从"不敢用"抬到"敢用"。

**33 残留**为什么要并进来：它零成本（文档+lint），但**不解决用户当下仍会踩坑**——`CHEATSHEET` 至今没写 `s[i]`/`len(s)` 已 O(1)、也没写"热循环先取局部变量"。不补，M106/M107 的收益只对知道内情的人成立。

## 2. S0：量化定标 + 零成本兜底

### 2.1 量化定标（**已执行**，2026-09-11）

#### ① Issue 34 —— **复现成立**（`/tmp/qgre`，M106 runtime，`taskset -c 3`，ms）

| 输入 | 不命中（无 `sk-`） | 命中（`sk-`+等长连续段） |
|---|---|---|
| 8 KB | 1 | 168 |
| 64 KB | 8 | **8862** |
| 1 MB | 115 | —（O(n²) 不可测） |

同一 64KB 命中输入对照：`{20,}`=8990 / `{20000,}`=8838 / **固定 `{20}`=0 / 纯字面=0**。
⇒ 8K→64K（×8）耗时 ×53（命中列），**O(n²) 确认**；引擎段 454 行（`rp_peek`…`bi_regex_find` 前）md5 = **`d147e921322cc70b536b155cf775f549`**，与清歌基线仓一致（M104→M106 未触正则引擎）。**S1 病灶钉死。**

> 注：本轮绝对值较清歌记录（10598ms）略低、`nok_1m` 偏高（115 vs 72ms），属机器负载差异；**形状（O(n²)）与对照结论完全一致**。

#### ② Issue 35 —— **不复现 ⚠️（重大更正，S2 价值重估）**

三轨实测（同一 1MB 输入，A=全局名直呼 / B=先取局部变量）：

| 轨 | 全局变量+全局名 | 全局部 | 仅全局函数 | A/B 比 |
|---|---|---|---|---|
| **VM（默认）** | **195 ms** | **105 ms** | 141 ms | **1.86×** |
| **C（--c）** | 97 ms | 20 ms | 53 ms | 4.85× |
| 纯算术基线 | — | 69 / 29 ms | — | — |

⇒ 当前 main 上**单次全局名访问 ≈40~50 ns**（全局函数 ~36 ns + 全局变量 ~54 ns），**不是**清歌所述 **1.4 µs**；1MB `bytes_get` 循环 **103~195 ms**，**已满足 Issue 35 §6 验收标准 #1（≤200ms）与 #2（def 100 万次 ≤300ms）**。

**根因交代**：`px_get_global` 的病灶（`for i<g_len` 线性 `strcmp`，源码注释记载**均值 2.08 µs**）**已在 M105-S2（`a4debda`，含于 tag `v0.2.0-m105` / `8cc7ba2`）改为 O(1) 哈希查表**。清歌记录的 **1638 ms ≈ 2.08 µs × 1M**，与**修复前**线性扫描完全吻合 ⇒ **疑其构建产物用的是 m104 期旧 runtime**（其节点当时确为 `0.2.0-m104`）；亦可能 `.rtcache` 未随 runtime 源重建。

**对 S2 的处置**：由"消除 13× 巨坑"降级为"**吃掉残余 ~1.9×（VM）的全局名常数**"。`CALL_SLOT`/inline cache 仍值得做（百万级循环 195→105ms），但**优先级低于 S1/S3**，且**验收标准须重写**（不得再引用 1638ms/13×）。→ 见 §1 修订。

mmap 59,361 / munmap 24,245（99.9% 单页）；sys 占墙钟 24%；GC 标记仅 ≈5%。详见 §3。

## 4. 语义红线（S1~S3 实施前逐条核对）

1. **正则**：`regex_find` 对外语义（含 `{n,}` 贪婪/回溯语义、捕获组、`ci` 大小写不敏感）**严格不变**；特化只在"可证明等价"的子集启用，否则回落原引擎。
2. `xmalloc` 返回槽**必须零初始化**（`gc_mark` 等字段依赖）——合并映射/内联后形式可变，**语义不可变**。
3. 槽地址 → slab 反查（`slab_find_locked` / `g_xfree_hint` 边界 / `g_slab_ranges`）在**映射布局改变后必须同步**；`slab_verify` 断言同步。
4. 精确 GC（M92）根面：`LXObject` 尺寸/union 布局变更需复核**所有** `sizeof(LXObject)` 处与 VM 帧槽扫描。
5. 并发路径：`g_slab_mu` 临界区不新增重入（`slab_raw_alloc` 不得改走 `xmalloc`）；`slab_reclaim_empty` 的"持 `g_gc_mu` + STW"前提保持。
6. `PX_GC_INLINE` / `PX_GC_THRESHOLD` / `PX_GC_DEBUG` 既有开关语义不变；新增开关默认 = 保守（可对拍还原改动前行为）。
7. **VM 调用点**：`CALL_SLOT` / inline cache 必须有**失效钩子**（重定义 `def`、动态装载后缓存不得失效）；`--no-cache`/解释轨行为与 VM 轨一致。
8. 跨轨一致：C 轨 `fn_*` 与 VM 轨（`vm.c`）共用 runtime ⇒ 改动**两轨同时**生效，须双轨冒烟。
