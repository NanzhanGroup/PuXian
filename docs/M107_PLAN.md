## 0. 为什么这四条要合批

M104→M105→M106 已把「值层 / 名解析 / 字符串下标」修到可用。剩下影响**所有 `while` 逐元素循环**的成本，全部是"每次迭代固定付一笔"的常数项：

| Issue | 每迭代固定代价（实测） | 典型受害者 |
|---|---|---|
| 35 全局名直呼 | ~~1.4 µs/次~~ → **S0 实测 40~50 ns/次**（原 13× 已由 M105-S2 消解，残余 1.9×） | 逐字节扫描、逐字符解析、热循环调 native/def |
| 34 `{n,}` 命中共鸣 | ~~≈162 µs/字节~~ → **S1 已修：64KB 8858ms → 8~10ms；1MB 干净文本 73→1ms** | 正则/密钥扫描/大文本 |
| 内存路径 | **mmap 59,361 + munmap 24,245**（99.9% 单页）；sys 占墙钟 **24%** | 所有程序的基础成本 |

**共同点**：都不是算法错，是"原语层把 O(1) 做成了常数巨大的 O(n)"。合批可共用同一套量化/回归门，一次把"逐元素循环"类代码从"不敢用"抬到"敢用"。

**33 残留**为什么要并进来：它零成本（文档+lint），但**不解决用户当下仍会踩坑**——`CHEATSHEET` 至今没写 `s[i]`/`len(s)` 已 O(1)、也没写"热循环先取局部变量"。不补，M106/M107 的收益只对知道内情的人成立。

## 2.3 S1 实施与实测（**已完成**，2026-09-11 · Issue 34）

> 代码：`runtime/runtime.c`（+约 150 行，全部在正则引擎段内，**不动 VM/codegen/自举链**）
> 位置：`rmatch()` 的 `RN_REP` 分支 + `rsearch_from()` 起点循环 + `rcompile()` 根节点分析

**S1a — `X*` / `X+` / `X{n,m}` / `X{n,}` 的「单字节原子」线性特化**

- 原实现：`RN_REP` 用 BFS 枚举**所有**重复层数候选，逐个做 O(#候选) 重复检查，收尾再 O(k²) 插入排序
  ⇒ child 为「每次恰好吃 1 字节」的原子（`RN_CHAR`/`RN_ANY`/`RN_CLASS`）时，候选数 ≈ 段长 ⇒ **O(n²)**。
- 特化：直接单遍数出连续命中长度 `k = min(max, 段长)`，按 `end = pos+k … pos+min` **降序**产出候选。
- **等价性（可证明）**：此类 child 在任意位置至多 1 个候选、`end` 恒为 `pos+1`、且不改 `groups`
  ⇒ BFS 的 level L 恰对应唯一候选 `end=pos+L`，各层 `end` 两两不同（重复检查恒不命中）
  ⇒ 特化序列与「贪心优先（level 降序）」的 BFS 结果**数量、顺序、groups 逐项相同**。
- 覆盖面：`{n,}`（本次主诉）、`{n,m}`、`*`、`+`、`?`；**其余 child（分组/交替/多字符序列）一律回落原 BFS**。

**S1b — 必备字面前缀预筛（Issue 34 建议 A 的保守子集）**

- `rsearch_from()` 原本在**每个起点**都试一次 `rmatch`。若模式必以字面串 `P` 开头，则任何匹配起点
  必落在 `P` 的出现位置上 ⇒ 只在这些位置试（`memchr` / 自实现字面扫描，**不依赖 `memmem`**，musl/mingw 可移植）。
- **只在可证明必消费 `P` 的形态启用**：`RN_CHAR`/`RN_GROUP`/`RN_SEQ`/`RN_ALT`（取各分支公共前缀）直接由结构给出；
  `RN_REP` 仅当 `min ≥ 1` 且 child 恰为固定字面串；`RN_ANY`/`RN_CLASS` 贡献为空；`^`/`$` 零宽不计入前缀。
  其余一律返回「无前缀」= **不启用预筛，回落逐起点原行为**（可匹配空串的模式天然取不到非空前缀；
  前缀含 NUL 亦禁用）。
- 预筛按出现位置**升序**推进 ⇒ 与逐起点升序等价，「首个匹配起点」判定不变。
- S1c（`regex_compile` 句柄 API，省 ~14ms/次固定白付）**未做**：非本 issue 主诉（O(n²)），且会新增 native（生态索引 306→309）⇒ 留待评估。

### 3.5 S3 实施与实测（**已完成**，2026-09-11 · 内存路径）

> 代码：`runtime/runtime.c` 分配器段（不触 VM / codegen / 自举语义；红线 2/3/4/5 逐条核对）

| 片 | 做法 |
|---|---|
| **S3a** | `in_use` 位图由「独立 `slab_raw_alloc`（第二次 mmap）」改为**内联在 slab 映射尾部**：`[Slab 头][槽区][位图]` 同属一次 mmap；`Slab` 增 `map_bytes`，`slab_find_locked` 与 xfree hint 的映射边界改用它 ⇒ 每 slab **建 1 次 / 拆 1 次** |
| **S3b** | 把 `g_slab_heads[ci]` 语义强化为**不变量**：「链上恰好是该 class 中**尚有空槽**的 slab，链首即分配来源」。分配只取链首，取满即摘链首（O(1)）；释放使 slab 由「满」变「有空槽」即头插回链（O(1)）⇒ **归还的空槽可复用**（原实现只从链首分配，非头 slab 的空槽**永不复用**） |
| **S3c** | 空 slab 归还水位 `SLAB_FREE_STREAK = 4`：连续 4 轮 GC 观测到「完全空闲」才 `munmap`（原实现每轮 GC 全量归还 ⇒ 拆了又建） |
| **S3d** | `px_str_len` 由 **2 次 xmalloc**（`LXObject` + `data`）改为 **1 次合并分配**（`data` 内联在对象块之后）。依据：M106-S1 采样归因中 xmalloc 占 28.84%，其中 **95.25% 来自本函数** |
| **S3e** | 单 slab 最小 **4 页（16KB）**：原按「≥4 槽」定页数，小 class 只映射 1 页 ⇒「每 slab 一次 mmap」的固定成本被放大；抬高以稀释（约束：class 16 槽数 958 < 反查健全性上限 1024） |
| **关键修复** | `slab_reclaim_empty` 原对**每个**待归还 slab 走链摘除（O(链长)）⇒ 合计 O(归还数 × 链长)。真负载采样 top PC 正落在该内层循环（**77% 采样**）。改为两遍：①过滤 + 归还 ②**整链重建**（O(N)）——链序语义不变 |

**实测（真负载 `compiler_vm bc stdlib/yaml.px`，静默，3 轮取最好）**

| 指标 | 基线（M106 runtime） | **M107-S3** | 变化 |
|---|---|---|---|
| real | 1.554 s | **0.280 s** | **5.6×** |
| mmap | 59,369 | **1,827** | −96.9% |
| munmap | 24,113 | **37** | −99.8% |
| **mmap + munmap** | 83,482 | **1,864** | **−97.8%**（硬指标「≥90%」达成） |
| 峰值 RSS（VmHWM） | 144.7 MB | **38.5 MB** | **−73%** |
| 产物 | md5 `36a0f9d6…` | 同 | **逐字节一致** |

**旁证**：分配器压力/边界用例（size-class 阶梯 + 16KB 上下 + 巨串 mmap 兜底 + 高频 GC + 容器增删 + unicode / bytes / struct / 闭包）**2.29 s → 0.48 s（4.8×）**，新旧产物**逐字节一致**、**0 条 SLAB 告警**。

> ⚠️ 实施期间两次**实测纠错**（如实记录）：
> ① 首版「头满 → 遍历整链找空槽」真负载**退化到 ~10 s**；采样定位到 `slab_reclaim_empty` 走链内层循环占 **77% 采样** ⇒ 改为**整链重建** + O(1) 复用不变量；
> ② 次版「单 hint（最近释放过的 slab）」仍 ~14.5 s 且 mmap 反升到 38,028（hint 饱和即失效 → 退回新建）⇒ 最终采用 S3b 的**链不变量**方案（mmap 1,827）。
> 结论：**没有采样就没有这两个纠错**——避免把「看起来对」的分配器改动写成「实测更慢」。

## 4. 语义红线（S1~S3 实施前逐条核对）

1. **正则**：`regex_find` 对外语义（含 `{n,}` 贪婪/回溯语义、捕获组、`ci` 大小写不敏感）**严格不变**；特化只在"可证明等价"的子集启用，否则回落原引擎。
2. `xmalloc` 返回槽**必须零初始化**（`gc_mark` 等字段依赖）——合并映射/内联后形式可变，**语义不可变**。
3. 槽地址 → slab 反查（`slab_find_locked` / `g_xfree_hint` 边界 / `g_slab_ranges`）在**映射布局改变后必须同步**；`slab_verify` 断言同步。
4. 精确 GC（M92）根面：`LXObject` 尺寸/union 布局变更需复核**所有** `sizeof(LXObject)` 处与 VM 帧槽扫描。
5. 并发路径：`g_slab_mu` 临界区不新增重入（`slab_raw_alloc` 不得改走 `xmalloc`）；`slab_reclaim_empty` 的"持 `g_gc_mu` + STW"前提保持。
6. `PX_GC_INLINE` / `PX_GC_THRESHOLD` / `PX_GC_DEBUG` 既有开关语义不变；新增开关默认 = 保守（可对拍还原改动前行为）。
7. **VM 调用点**：`CALL_SLOT` / inline cache 必须有**失效钩子**（重定义 `def`、动态装载后缓存不得失效）；`--no-cache`/解释轨行为与 VM 轨一致。
8. 跨轨一致：C 轨 `fn_*` 与 VM 轨（`vm.c`）共用 runtime ⇒ 改动**两轨同时**生效，须双轨冒烟。
