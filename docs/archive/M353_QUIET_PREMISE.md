## 三 逐门结论

### 1. m183_gc_root_handover —— 留 quiet，改「补前提断言」路线

三轮的失败点**完全相同**，且不是产品回归：

```
❌ 负控 A · px_root_pop 退回「立即收缩」（恢复缺陷 197） ⇒ **未判红**
   （负控失效：该处并非本门覆盖的根因）
PATCH-B-OK / 负控 B/C/D 判红 ✓ / ⑦ 源逐字节还原 ✓（71bab5b6a2d45727）
M183-VERIFY-FAIL
```

⇒ **判据在分片负载下失去了鉴别力**：负控 A 造的那个「立即收缩」缺陷没被观察到，
而本门空闲单跑恒绿（quiet 档历史一直绿）。这不是「机器慢了一点」，是**负控的时序前提没被断言**
（口径 12 的同族）：负载让「收缩发生时刻 vs 根栈仍有持有」这个窗口被饱和 ⇒ 缺陷 197 的路径根本没被走到。

处置（下一轮落地，本轮只定性 + 登记）：
- 负控 A 改**结构性**造（口径 13）：不靠「跑得快时才能撞见」，改成「注入后**必须**在该轮出现 N 次收缩事件」
  并断言「收缩事件发生时根栈非空」；前提不成立报 **ANOMALY/PREMISE-FAIL**，既不许报绿，也不许报产品红。
- 在负控通过之前，本门**继续留在 quiet 档**（它是负载敏感的真证据，不是藏问题）。

### 2. m280 / m208 —— 3/3 绿，但**不移档**

草案 §五 写明的移档前置条件是两条，缺一不可：
1. **分片档下连跑 N 轮全绿**（本装置给了 3 轮；m280 的另一半 —— `[3c]` RSS 收敛 —— 历史命中率低，按草案要 **5 轮**才谈得上）；
2. **该门判据在负载下仍有牙**的负控（口径 9：缩小剂量必须翻转）。

本轮只有第 1 条的一半。⇒ **本轮不移动**，理由写死在这里，避免下一轮又被「3 轮绿了」说服：
- m280：`[3c]` 对「外部重活」敏感（M307 r4 dnf-makecache 期间红过），3 轮分片绿**不覆盖**该形状；
- m208：两次「负载 ⇒ LIVECHK」历史，且 LIVECHK（读到已回收对象）是**真·不安全读数**，代价最大。
  收益只有 ~200s/轮，不值得拿「真读数」去赌。

下一轮若要推进：先做**负载负控**（对 m280 `[3a]/[3c]` 缩剂量必须翻转；对 m208 造一次「必 LIVECHK」的结构注入，
证明判据仍能红），再补 2 轮（合计 5 轮）。两条都到手才改表。

### 3. m244 / m267 / m302 —— 结构性不动

m267 的性能基线是**空机采的**（V5 已实测 C 轨同慢）；m244 自己就测加速比；m302 靠门内并行吃饭
（JOBS=2 ⇒ 901s 撞 900s 上限）。三者与分片档**结构性冲突**，3 轮绿或红都不改变这个结论。

## 四 口径层面的结论（比移档更重要）

1. **quiet 档自身是一个未断言的前提**：它假设「分片会假红」，却从不检查「此刻机器是否被压」。
   正确做法（口径 12）：跑 quiet 每门之前采样 `loadavg`，> 阈值（建议 2.0/核）⇒ **响亮报 ANOMALY 并顺延**，
   而不是静默跑出一堆假红。这是**防假红**，不是放宽。
2. **移档 = 更换假绿/假红环境，不是消除风险**：没有「负载负控」的移档，等于把门搬到另一种假绿里。
3. **不许为省时间放宽阈值**（M352 已复述）；quiet 档 10 门合计 1544s ≈ 25.7min 是**上限**，
   不等于移档净收益（移回分片后仍在跑，只是并行）。

### 7.2 新判据（两腿都要过；max 降级为诊断量）

`packaging/loadavg_verdict.sh`：

- **[P] p95(loadavg 1m) ≤ 2.0 / 核**（nearest-rank，centi-load 直方图，不依赖 gawk `asort`）
- **[R] 越界采样占比（≥2.0/核）≤ 5%**
- 诊断：`max > 8.0/核` ⇒ 打 `diag=ANOMALY`（**不判红**，只留定位线索）
- **样本下限 30**：不足 ⇒ `rc=2 INVALID`（不许拿 3 个点判绿 —— 这是防「换判据顺手放水」的第二道门）
- 退出码：0 全 PASS · 1 有 FAIL · 2 输入无效；`LOADAVG-VERDICT=` 末行供链尾/CI 抓取

**quiet 门内口径 12 的瞬时断言（2.0/核 ⇒ 报 ANOMALY 顺延）不动**，理由写实：那是**逐门前提检查**、
命中的动作是「顺延」不是「判红」，观察单位是单门；整链判据的观察单位是整轮。两者语义不同，
合并会把「机器此刻有点忙，把门挪到后面」和「这一轮整体不可信」搅成一件事。
（§7 待判项「是否要连续 2 次采样越界才报」⇒ 判为**不做**：quiet 档已按门顺延，加跨门状态收益 < 复杂度。）

### 7.5 M361 首跑假红复盘：判据的**分母与分子不同界**（缺陷 626 · 同轮收口）

首跑全量门（8 分片，`/data/gatevm/chain-m361-20261030-061019-3473903`）判 **NO-GO**：绿 236 / 红 1，
红的是新门自己 —— `pkg_loadavg_verdict` 报 `SELFTEST FAIL（11 条失败 / 30）`，而**同一份脚本在本机手跑 30/30 PASS**。

11 条失败全在「本应 PASS」的档（[1a][1b][2a][2b][2c][2d][2f][4b][5a][5c][7a]），量纲上看就是**每核值整齐放大 8 倍**：

```
n=465  median=8.30  median_pc=4.15  p95=8.30  p95_pc=4.15  over=465  over_pct=100.00  verdict=FAIL
```

`8.30 / 4.15 = 2` ⇒ 判据把核数当成了 **2**。根因链条：

1. 判据默认核数取 `nproc`；`nproc` 读的是 `sched_getaffinity`，**只看本进程能用的核**；
2. `packaging/chain/shard_run.sh` 每路 `taskset -c` 绑 2 核（16 核 / 8 片）；本机手跑不绑 ⇒ 16；
3. 分子 `/proc/loadavg` 是**全系统**负载 ⇒ 分母被绑核压到 1/8 ⇒ 每核值 ×8 ⇒ p95 腿、占比腿同时爆。

**这是量具口径错，不是阈值松紧**。修法（不放宽任何阈值）：
分母改成 `online_cpus()` —— `/sys/devices/system/cpu/online` 解析（`0-15` / `0-3,8-11` 都吃得下）
→ 回退 `getconf _NPROCESSORS_ONLN` → 最后才 `nproc`；口径原则写进脚本头注释：**分母必须与分子同界**。
`--nproc` 仍可显式覆盖（宁可显式，不许在受限环境里静默按子集算）。

三层自证/负控（自证 30 → **34 断言**）：

| 项 | 做法 | 结果 |
|---|---|---|
| [11a] 回归有牙 | `taskset -c 0,1 nproc` 必须 < 全机核数 | ✅ 2 < 16 |
| [11b][11c] 绑核回归 | `LVA_SELFTEST_SUB=1 taskset -c 0,1 bash selftest…` 整份重跑 | ✅ rc=0、`SELFTEST PASS` |
| [11d] 分母同界 | 绑核子进程里判据聚合行仍须报 `核数 16` | ✅ |
| 结构性负控 | 副本把 `online_cpus` 换回 `nproc`（即首跑现场）跑新自证 | ❌ 3 条失败（[11b][11c][11d]）⇒ 回归能抓住旧写法 |

**附带修**：链尾 `/data/autodrive/m361_chain_wrap.sh` 调判据原不带 `--json`，而默认表格行是
`p95=0.96/c 越界=2.98%` ⇒ 解析 `p95_pc=`/`over_pct=` 得**空**（首跑 `M361-chain-extra.log` 里
`p95_percore= over_pct=` 就是这么空的）。已改为 `--json` 再解析，诊断量不再丢。

**教训（进台账）**：判据在「本进程视角」下全绿 ≠ 在「门的运行环境」下全绿。
凡分母取自系统量（loadavg / 内存 / 文件数），必须显式声明它与分子的**同界口径**，
并把「受限环境（绑核 / cpuset / 低 JOBS）下重跑一遍」写成自证的一条断言 —— 否则分片门就是它的照妖镜。

### 7.6 M361 r2 再次假红复盘：**量具只修了一半**（缺陷 627 · 同轮收口）

r2（07:28:56 起 · unit `chain-m361r2` · HEAD `ac06841` · 08:44:13 收）仍 **NO-GO**：`reason=shard-rc-1`，
红门还是 `pkg_loadavg_verdict`，但这次只有 **2 条**失败，且形状与 626 完全不同：

```
── [11] 绑核回归：taskset -c 0,1 下整份自证仍须全绿
  ❌ [11a] 绑核生效（子跑 nproc=2 < 全机 2）（期望 [yes] 实得 [no]）
  ✅ [11b] 绑核下自证 rc=0   ✅ [11c] 绑核下全绿
  ❌ [11d] 绑核下分母仍是全机核数（[… 核数 16] 不含 [核数 2]）
SELFTEST FAIL（2 条失败 / 34）
```

关键点：**判据侧已经对了**（[11d] 的红信息里判据报的是 `核数 16`，正是期望值），
错的是**自证自己**：`packaging/selftest_loadavg_verdict.sh` 里 `NC=$(nproc)` ——
它在分片环境（整门被 `shard_run.sh` 的 `taskset -c` 绑在 2 核上）里得 **2**，于是「全机核数」= 2：
[11a] 拿 `2 < 2` 判「绑核生效」必假；[11d] 期望字符串变成「核数 2」，而判据如实报 16 ⇒ 必红。

**口径**：同一根因（`nproc` 读 `sched_getaffinity`，只代表本进程可用核）出现在**两处**，
626 只扫了判据侧。修法同口径 —— 自证加 `machine_cpus()`：
`/sys/devices/system/cpu/online` 解析 → `getconf _NPROCESSORS_ONLN` → `nproc` 兜底。
自证不变宽松，断言数仍 34，只是「全机」这个词终于指全机。

证据（本轮实测）：

| 项 | 做法 | 结果 |
|---|---|---|
| 正控 A | `bash packaging/selftest_loadavg_verdict.sh`（不绑核） | ✅ 34/34 |
| 正控 B | `taskset -c 0,1 bash packaging/selftest_loadavg_verdict.sh`（复刻分片：整门绑 2 核） | ✅ 34/34（修前此处 2 条红，与 shard5 现场同形） |
| 负控 C | 副本把 `NC=$(machine_cpus)` 换回 `NC=$(nproc)`，再绑核跑 | ❌ [11a][11d] 红 · rc=1 ⇒ 回归有牙 |
| 口径核对 | 绑核下 `nproc=2` / `getconf=16` / `/sys/.../online=0-15` | 三者关系符合预期 |

**教训（进台账，补第 19 条口径的续句）**：改量具要先问「这个量在生产环境里被谁用、被谁复制」。
判据与自证是两份取同一口径的代码 —— **只改一份，另一份就成了新的假红源**；
凡「全机 / 总内存 / 总核数」这类系统量，**全仓 grep 一次 `nproc`**，逐处标「这是并行度（该看 affinity）」还是「这是分母（该看全机）」。
