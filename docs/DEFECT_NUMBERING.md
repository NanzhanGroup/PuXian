# 缺陷编号纪律（M241）

> 为什么需要一份单独的文档：**缺陷编号是本仓最常被引用的"坐标"** —— 代码注释、CHANGELOG、
> 门、报告、给第三方的回执都用它定位「哪一轮修了什么」。编号一旦指错，读者会落到
> **完全无关**的里程碑上，而**任何编译/对拍/冻结门都不会红**（它不改变行为、不改变产物）。
> 这与 M185「错误信息指不到根因」同族 —— 只不过指向错误的对象是**注释**。

## 一 编号规则

1. 缺陷号**全局单调递增**，跨里程碑不重复、不复用。
2. 一个里程碑在自己的 CHANGELOG **标题行**里声明它占用的编号集合，写法自由但必须能解析：
   - `（缺陷 395–399）` · `（缺陷 268 / 269 / 270）` · `（缺陷 234 + 235 + 229）` · `（缺陷 259–264 · 266）`
   - 只**登记**（本轮编号、后续轮收口）的也写进标题，例如 `· 登记 265/267`。
3. **`s` 变体**（`M235s1`）也应当有自己的标题行 —— 否则它的编号在判据里只能走 SKIP（M235s1 就是这个缺口，
   M241 补齐）。

## 二 引用规则（源码注释）

- 写法：`M<里程碑>（缺陷 <号>：<形状>）`，或 `M<里程碑>（缺陷 <号> <补充说明>）`。
- **「最近的那个里程碑标记」决定归属** —— 所以交叉引用要把被引用的里程碑写在号的前面：
  - ✅ `M240（M235s1 缺陷 354 的镜像面）` —— 归 M235s1
  - ❌ `M240（… 见缺陷 269）` —— 归 M240，而 269 是 M208 的 ⇒ 判红
- **对方问题单的编号不是本仓编号**：`qg-issue 87 缺陷 7` / `第三方缺陷 018…030` 一律跳过
  （判据要求外来标记**紧贴**「缺陷」才跳过 —— 否则会把自己的声明也毙掉）。
- **「家族标签」不是正式编号**：`M207 记账为「缺陷 267 家族」` 这种，若不想参与判定就不要写「缺陷 267」
  这个形状，或把该号补进相应里程碑的标题声明。

## 三 判据

```bash
python3 selfhost/check_defect_refs.py --self-test   # 11 条夹具（含判据自身踩过的 5 个坑）
python3 selfhost/check_defect_refs.py               # 真仓：判定 N 条 · 跳过 M 条 · 违例 0
```

- 退出码：`0` 无违例 · `1` 有违例 · `2` 用法/输入错 · **`3` 判据自身失效**（CHANGELOG 一条声明都没解析出来）。
- 注册在 `selfhost/m116_gates.sh` 与 `.github/workflows/ci.yml`（toolchain job）。
- 覆盖面：`runtime/*.c` · `runtime/*.h` · `selfhost/*.px`。**`examples/` / `docs/` / `tools/` 未纳面**（下一轮候选）。
- 只认**自带标题**（`^#+\s*M<num>`）—— 交叉引用小标题（`### 二 派生索引（M235s1 缺陷 355 的教训）`）不构成声明。
- 解析不出声明集合的里程碑 ⇒ 它的引用整批记 **SKIP 并响亮计数**（不是静默放过）。

## 四 改判据的纪律（本仓通用）

- **改判据必须配反向判据 + 判据回放**（M209）：只改判据容易把「假阳」改成「假阴」。
- **「找不到」先怀疑判据**（M207）：本判据第一版把 M208 解析成 `{268}` ⇒ 121 条假阳。
- **新计数键必须同步合并/汇总逻辑**（M214）。
- 判据自身的 bug 要**留成永久夹具** —— 本判据的 `--self-test` 有 11 条，其中 5 条就是它自己踩过的坑。
