## 二 从这 6 条抽出的四条口径（可直接当 review checklist）

1. **观测窗口 ≥ 现象的随机性**：时间窗口/CPU ticks 类判据必须多轮取样，任一命中即判红；
   不要用「单轮结果」下「判据没有牙」这种结论。
2. **就绪判据必须等于被测通道**：日志打印 READY ≠ 端口可连；两者要分别自证（m150）。
3. **同一门里对同一事实只读一次**：静态断言读一次快照，别反复 `cat` 工作树（m278）。
4. **前提断言先于症状断言**：注入类负控先断言「注入装上了 / 命中了」，再断言症状（m128 的 `/arm` + `注入命中`）。

### 二·补 M341 修正：上面四条**不够**，真正的两轴是这两条（缺陷 597）

M340 时我写的是「主要风险面在时间量判据」。M341 实测 216 个已注册门后，这条被自己的数字推翻：
**6 个已定性案例里只有 1 个（594）涉及时间量**，其余 5 个的病根是「单次取样」或「判据通道 ≠ 被测通道」。
⇒ 台账从「按时间量过滤」改成**两轴过滤**，请按这两条 review，不要按时间量找：

5. **取样次数 ≥ 现象的随机性**：现象本身是概率性的（并发 / 竞态 / 信号 / EOF 时机 / 调度 / 隔离），
   **一次观测就下结论 = 判据在上报「这次没抽中」**。判定口径优先用「N 轮内任一命中即判红」，
   并把每轮数值打出来；「重试到绿」是掩盖，不是处置。
6. **判据通道 = 被测通道**：断言读的那个东西，必须**就是**要证的那个东西。
   反例：日志出现 READY ≠ 端口可连（m150）· 用 UDP 探针证明「网通」却去测 TCP 回退（m116 D5）。
   做法：就绪/前提类断言各自**单独自证一次**（正控 + 负控都写）。

`selfhost/flake_rerun.sh`（动态频次）。detail 见 `docs/GATE_FLAKINESS_AUDIT.md`。

### 二·补 M343：第 7 例是「**判据读了两个不是一回事的数字**」

599（m317 [5.3]）的病根既不属于「时间量」也不属于「取样次数」，而是**第 6 条的变体**：

于是「严格相等」这条断言把「计数语义」当成了「产品行为」。
⇒ 补第 7 条口径：

7. **断言两个数相等前，先证明它们的生产者是同一处**。若一方有多个自增点（不同路径），
   相等只在「另一些路径从没跑过」时才成立 —— 那是**前提**，必须单独断言（或改成差额界）。

同时第 3 条（同一事实只读一次）在本例里被我误解成「两次采样要一致」——
**错**：计数本身就是单调递增的，「两次相等」永不成立（首版当场自伤判红）。

### 二·补 M344：第 8 例（缺陷 600）是「**窗口比被测现象的抖动还短**」，而且单位写错了

### 二·补 M348：第 11 条口径 —— **进度标记由「起点」写，不由「终点」写**

11. **任何「完成 / 进度」标记必须在动作开始时就能写，不能挂在「后面每一步都成功」上**：
    - 长流程先落 `STARTED`（含口径、N、命令原文），成功再补 `DONE`，失败写 `FAILED reason=`；
    - 标记与产物**解耦写**（产物坏了标记照样落地，人才能看见「坏了」而不是「没动静」）；

### 二·补 M349：第 12 条口径 —— **判据必须断言自己的时序前提，尤其是「这段时间里没人回收」这类**

611 的形状值得单独记：门要证「槽位不释放」，装置靠「客户端静默退出」造出「不释放」，
但**真正决定槽位还在不在的是服务端的回收时机**，而这件事门从头到尾没有断言过。

```
负载低：段时长 < 回收阈值 ⇒ 槽位填满 ⇒ 第 257 个失败 ⇒ 门绿（看起来在证明产品）
负载高：段时长 > 回收阈值 ⇒ 槽位被回收 ⇒ 一次都不满 ⇒ 门红（看起来产品坏了）
同轮 [5]（优雅关闭 264/264）恒绿 ⇒ 产品回收路径正常，坏的是 [6] 的装置前提
```

两条可直接搬用的判据：

1. **时序前提要在门里写成断言**（而不是写在注释的立论里）：凡「我先制造一个不利状态，然后看后果」
   的判据，都必须断言那个不利状态**在被观察的整个窗口内仍然存在**。
2. **判据失效的方向要偏向「响亮」**：前提不成立时报 ANOMALY（区别于产品红，但**照样不是绿**）。
   611 最危险的地方是失效时门更绿 —— 与 600/602 同族，但这次连「红」都没有，直接白给。

### 二·补 M350：第 13 条口径 —— **装置的「不利状态」要用结构造，不要用时序等**

611 的修法有两个候选：① 结构确定性（连接**活着** ⇒ 槽位必然被占）② 加前提断言（前提不成立报 ANOMALY）。
M350 先做 ①，把 ② 留作兜底 —— 结论是 **①能做就别只做②**：

```
旧装置：[6] 串行 264 次「静默退出」，指望「进程退出后槽位不释放」
        └ 这句话的真假取决于服务端回收时机（2×PX_H3_IDLE_MS），而门管不了它 ⇒ 时序依赖
新装置：单进程持握 256 条（连接活着 + 未发 CONNECTION_CLOSE），第 257 条打一次
        └ 槽位被占是**进程存活**的直接后果，与任何定时器无关 ⇒ 无时序依赖
实测（/data/gatevm/m350_replay/，6 轮）：3 base + 3 × +8 路 hog ⇒ **6/6 全绿**
        建立 256 条 1.8–2.1s（hog 下 2.1s）；判据窗口 2.3–2.7s ≪ 回收窗口一半 60s；释放后 26–45ms 恢复
对比（M349 同条件 3 轮）：旧装置 hog 下 **3/3 红**，且失败项恒为「没有一次失败」
```

三条可直接搬用的判据：

1. **能结构造的不利状态，别用「等出来的」**：凡是「我先让某个资源被占满/某个窗口持续」的装置，
   优先让它由**对象的存在性**决定（进程活着、文件存在、锁held），而不是由「在这段时间里没人动它」决定。
   后者每多一个依赖就多一个失效面，而失效时门通常是**更绿**（611）。
2. **前提断言要能区分「装置坏了」与「产品坏了」**：M350 用 `prem()`（⛔ + `ANOMALY（前提不成立 · 不是产品红）`），
   同样判红、同样不进「通过」，但措辞让人一眼看出该修哪一边。三条前提：
   P1 持握 256/256 全 OK · P2 判据时刻持握进程仍存活 · P3 判据窗口 < 回收窗口的一半。
3. **判据要有鉴别力，且鉴别力要当场自证**：NC-D 只持握 64 条 ⇒ 第 257 条**必须被接受**。
   只有 64「接受」+ 256「拒绝」这对对照成立，[6] 才是在证明「上限 256」而不是在证明「这个门恒红」。
   （口径 9 的加强版：不只是「负控能判红」，还要「缩小剂量时判据会翻转」。）

**装置规模的坑（本轮实测，值得记）**：最初想用 256 个并发**进程**各持一条，结果 63/256 建连失败或崩溃
（loopback UDP 收包被压塌，79s 仍未建满）—— 噪声盖过判据，且看起来像产品坏了。改成**单进程顺序建连 + 全部持握**
后同一件事 1.9s 完成、0 失败。教训：**装置自身也是被测对象**，它的失败模式必须先被量一遍。

### 二·补 M352：第 14 条口径 —— **判据的「装置态」也要自证（空输入 / 全红 / 被杀 / 产物缺失）**

615、616 是同一类：**判据/参数通道在「非正常态」下静默走偏**，而两个都是 V5 负控装置自己撞出来的。

```
615  shard_run.sh 给 0 门的分片拼出 `--only ''` ⇒ run_gates.sh 把空值当「不过滤」
     ⇒ 空片跑了 30–34 门全量门（实测 shard5..8.log 绿 31/31/32/34），日志一个字不提示
     ⇒ 危害双重：白烧 4 份全量（成本）+「这轮跑了什么」失真（M342 的口径被架空）

616  SH_OK=$((SH_OK + $(grep -cE '…' f || echo 0)))
     grep -c 无匹配时**自身已输出 `0` 且 rc=1** ⇒ `|| echo 0` 再补一个 ⇒ 子命令两行
     ⇒ syntax error in expression (error token is "0")，而紧随其后就是「空跑必红」裁决
     ⇒ 触发条件平凡：**任何一片全红**（真灾难）就命中
```

两条可直接搬用的判据：

1. **空值 ≠ 默认值**：凡「可选参数 / 过滤器」的**显式空值**，一律判死（rc=4 + 指明缺陷号），
   不许落回「不过滤 / 跑全部」这种**更贵**的默认。落回更贵的默认值 = 失效方向偏贵，不是偏红。
2. **`grep -c` 的返回值陷阱要当模板记**：`grep -c` 是**唯一**「无匹配也打印数字且 rc=1」的常用命令
   ⇒ `$(cmd || echo 0)` 在它身上必然产出 `0\n0`。凡汇总数字，先 `_n=$(…) || _n=0` + 非数字兜底，再入算术。
3. **本轮的元教训**：判据整治任务里，**负控装置本身也会暴露判据通道的缺陷** ——
   615 是「装置要跑 8 片但只有 4 门」撞出来的，616 是「一片全红」撞出来的。
   所以装置跑完**必须回头读自己的汇总段**，而不是只读被测门的结果。
4. **取不到 ≠ 没有**（617）：装置统计自己的产物时，路径必须由「产物实际落点」决定；
   产物缺失要**判死**（`MISSING-ARTIFACT`），不许计 0。凡 `2>/dev/null || echo 0` 把
   「命令失败 / 路径不存在」折成「事实为零」的写法，都是同一陷阱家族 —— 而这里的零正好等于「一切正常」。

### 二·补 M353：第 15 条口径 —— **取证步骤的执行状态必须与结论分开**

618 的形状是新的，也是这一族里最阴的一条：**判据的逻辑没错，错的是「读取答案」这个动作的退出码**。

```
printf '%s\n' "$code" | grep -qF -- 'TG + TR'      # set -o pipefail 下
```

`grep -q` 命中即退出 ⇒ 上游 `printf` 的写操作可能失败 ⇒ `printf` 返回 **1**（实测 `PIPESTATUS=(1 0)`）⇒
`pipefail` 把整条管道判成非 0 ⇒ 判据读到「未命中」。
**它只在负载下出现**（48 路 CPU 压着跑：`4/60` 轮；空机连跑 4000 次 0 例）—— 正是「假红只在高负载全量门里出现」的模板。

15. **取证（读答案）与结论（下判断）必须分成两件事，且取证的失败必须自带名字**：
    - 判据读答案时**不用管道传递被测数据**（here-string / 临时文件），别让 `pipefail` 把上游写失败算进结论；
    - 命令退出码只允许映射成三态：**命中 / 未命中 / 取证工具失败**。第三态**不许**冒充前两态，
      报出来的措辞要能直接看出「这不是结论」（本轮：`取证工具失败（grep 异常 · 非结论）`）；
    - 凡「解析/抽取」出来的东西（函数体、产物、表格），**先断前提**再拿去判：抽不到就报
      `EXTRACTION-FAIL` / `PREMISE-FAIL`，不许静默退化成「判据被删」或「一切正常」（口径 14 的第 5 个面）；
    - **装置本身要有频次数据**。`shard_gate_verdict --self-test` 是每个分片都跑的装置：它假红一次，
      白烧一整轮全量门（≈92min），且红的是「判据被删」这种最吓人的理由。所以「装置绿」也要被量：
