# 门间隔离（Gate Isolation）

> 建立于 M264；来历 = M260 §八 候选 ③「门之间的残留干扰」。
> 判据工具：`selfhost/check_gate_shared_tmp.sh` · 白名单 `selfhost/gate_shared_tmp.txt`（§一–§七）；
> `selfhost/check_gate_lock.sh`（§八 门级互斥 · M276）。

## 一 为什么「单独跑全绿、串起来跑却红」

全量门是**一串子进程**，它们共享同一个文件系统、同一批端口、同一份 `/tmp`。于是：

- A 门留下的**文件/目录**（固定 `/tmp` 路径）会**改变 B 门的行为**；
- A 门留下的**进程**会占住 B 门要用的**端口**；
- A 门改过的**共享构件**（如开发缓存）会让 B 门测到别的版本。

⇒ 出现**不可复现**的失败。M260 实测过一例：**m157（ONNX）跑完后 m260 的探针 5/5 被杀**，
而单独跑 m260 全绿。

## 二 判据：**白名单制**

> 共享**不一定**是坏事（开发构件缓存、外部大模型都是**有意**共享）。
> 但**必须显式登记 + 写理由** —— 否则「共享」就成了隐形的耦合。

| # | 判据 | 违反时 |
|---|---|---|
| **J1** | 被 **≥2 个门**共用的固定 `/tmp` 顶层名**必须在白名单** | 判红（**指名**哪几个门） |
| **J2** | 白名单每条必须有**非空理由** | `rc=3`（判据失效：无理由豁免 = 把红当绿） |
| **J3** | 白名单**过期**（登记了但实测 ≤1 门在用） | 判红（防「把红当绿记下来」） |
| **J4** | 规模锚点（门数 ≥150 · 共用名 ≥1） | 判红（防判据静默变空） |

自证 **4/4**（未登记必红 · 登记后绿 · 过期必红 · 无理由 `rc=3`）。

## 四 修法示范：把「共用」变成「参数化」

M264 修掉的那一处：`examples/m260_gc_repro/` 复用 `examples/m256_eintr/probe_eintr.px`，
而探针里**硬编码** `D = "/tmp/px_m256_probe"`。

```python
# 修后（probe_eintr.px）
var D = "/tmp/px_m256_probe"
let _m256d = env("M256_PROBE_D")
if _m256d != null:          # ⚠️ 必须**先查 null**
    if _m256d != "":
        D = _m256d
```

```bash
# 修后（m260 的 verify.sh）
mkdir -p "$W/probe_d"
M256_PROBE_D="$W/probe_d" ... "$BLD" ...
```

> ⚠️ **踩过的坑**：`env()` 未设置时返回 **`null`**，而 **`null != ""` 为 `true`**
> ⇒ 只查 `!= ""` 会把 `D` 赋成 `null` ⇒ 探针**启动即崩**（门从 14/0 掉到 **5/14**）。
> **改一处语料 ⇒ 必须复跑它所属的门。**

## 五 ⚠️ 静态扫描器的自伤（第 6 条）

**注释/文档里复述的旧路径会被算成「引用」** ⇒ 把**已经修好的门**读成「仍在共用」⇒ **假红**。
本轮实测两次：① 说明注释里有旧路径；② 两行 `echo` 字符串里有旧路径（引号**跨行**）。

⇒ 处置：
1. 扫描器加「**quote 感知的行内注释剥离**」；
2. **门里不复述旧路径的字面量**（要说就写「同一条固定数据目录」）；
3. 剥离器的**已知边界**（跨行引号）写进守卫头注。

## 六 覆盖边界（如实）

- 本判据是**静态**的（扫 `examples/*/verify.sh` 与 `examples/*/*.px|.sh` 的 `/tmp` 顶层名）。
- **共用端口**不在判据内：例如 m260 固定用 `18420/18421`，那是**有意**的，并且已在它自己的
  覆盖边界里写「**不可并行跑**（本门串行）」。若要判据化，需要另一套「端口清单」白名单 —— **下一轮候选**。
- 「A 门留下进程占端口」这类**运行时**干扰，静态判据看不见 ⇒ 需要**动态**层
  （例如门结束后检查「新增的监听端口」）。**下一轮候选**。

## 七 写新门时的清单

1. `/tmp` 路径带**门名或 `$W`**（运行期目录），不要用裸固定名。
2. 真要跨门共享，先在 `selfhost/gate_shared_tmp.txt` 登记 + 写理由。
3. 端口要么用 `$W` 派生，要么在门的「覆盖边界」里写清「不可并行」。
4. 门结束前**清理自己写出去的东西**（仓库内的新增文件尤其重要 —— 见 M207 的运行副作用清理）。
5. 改完跑：`bash selfhost/check_gate_shared_tmp.sh --self-test && bash selfhost/check_gate_shared_tmp.sh --root .`
6. 门开头 source **门级互斥锁**（M276 · 见 §八）：
   ```sh
   . "$(dirname "$0")/../../selfhost/gate_lock.sh" || { echo "❌ [M276] 门级互斥锁 source 失败" >&2; exit 2; }
   ```
   （守卫 `check_gate_lock.sh` 会判：**每个门**都必须 source、且必须在改源码的标记**之前**。）

## 八 门级互斥（M276 · 晨曦 2026-10-05 回馈）

> 晨曦原话：「门有并发不安全性（**就地改仓库**，建议加锁或 mktemp 副本）」。

§一 列了隔离的三个面（**文件** / **进程与端口** / **共享构件**），但**「同时有两个人改同一份源码」**这一面
此前**只有一半护栏**：

| 场景 | M276 之前 |
|---|---|
| 两个**全量门**并发 | ✅ `run_gates.sh` 的 PID 锁（M191 立） |
| **人工单跑**一扇门 + 全量门在跑 | ❌ **无覆盖** |

而本仓 **98 个门**会在负控里**现场改源码**（`restore_all` / `NEGCTL` / `run_neg` …）。实测代价
（M191 / M213 / M221 / M223 **各撞过一次**）：负控的 `snapshot/restore` 会**盖掉**未提交改动；
门会读到**别的门打的负控补丁**（中间态）⇒ 假红 / 假绿；abort 时残留 `NEGCTL-*` 会被烘进入库件。

### 机制

```sh
# 每个门开头（在任何改源码的动作之前）
. "$(dirname "$0")/../../selfhost/gate_lock.sh"
```

- **全量门**（`run_gates.sh`）**持有同一把锁**并导出 `PX_GATE_LOCK_HELD=1` ⇒ 门内直接返回（不重复加锁）
- **单跑门** ⇒ 抢锁；抢不到 ⇒ **`rc=2` 响亮退出**（默认**不等待** —— 全量门要跑 ~2h，
  静默阻塞看起来就像挂死）；`PX_GATE_LOCK_WAIT=<秒>` 可改成轮询等待
- 拿到锁后**导出** `PX_GATE_LOCK_HELD=1` ⇒ 本门派生的子进程（重烘 / 子脚本）不再抢锁

### ⚠️ 为什么是「PID 文件」而不是 `flock`（本轮实测后改的设计）

第一版写的是 `exec 201>lock; flock -n 201`。实测**两个致命问题**：

1. **锁会随 fd 泄漏给后代** —— 门里 `setsid nohup px_serve &` 那类**后台进程**继承 fd 201，
   门退出后它仍持锁 ⇒ **下一扇门无端失败**。`flock` 是 open-file-description 级的，
   而 bash 没有语法给 `exec N>` 设 `FD_CLOEXEC`。
2. **释放只能靠进程退出或 `trap EXIT`**，而 **`trap EXIT` 会盖掉门自己已有的 EXIT 陷阱**
   （大量门用它做 cleanup）⇒ 要么破坏门，要么泄漏。

⇒ 改用**只认「持有者 PID 还活着吗」**的文件锁：后台子进程**不影响**它，也不需要 `trap`
（陈旧文件由**存活判据**自愈）。存活判据 = `kill -0` **且** `/proc/<pid>/cmdline` 像门
（后者防 **PID 复用**把陈旧锁误判成「被占」⇒ 所有门永久被挡）。

### 判据（`selfhost/check_gate_lock.sh`）

| # | 判据 | 违反时 |
|---|---|---|
| **J1** | **每个** `examples/*/verify.sh` 必须 source `gate_lock.sh` | 判红（**指名**） |
| **J2** | source 行必须在**第一个改源码标记之前** | 判红（在标记之后 source = 白 source） |
| **J3** | 规模锚点（门 ≥190 · 含标记门 ≥90） | 判红（防判据静默变空） |
| **J4** | `run_gates.sh` 必须**持有**同一把锁（只 export 不持有 = 等于没锁） | 判红 |
| **J5** | `gate_lock.sh` 存在 | 判红 |

门 `examples/m276_gate_lock/`：**32 通过 / 0 失败** —— 行为五组（抢到 / 并发被拒 / 陈旧自愈 /
已持跳过 / **后代不继承**）+ **竞态**（10 进程同启 ⇒ 恰好 1 个）+ `run_gates.sh` 集成（持锁拒启 ·
对照已持放行）+ **3 道负控各自独立判红**。

### 覆盖边界（如实）

- 锁是**全局单把**（不按仓库根分键）⇒ 两个 git worktree 会互相串行。**有意**：分键要
  runner / gate 两处各算一遍，**算不一致就是静默失效**（没有保护还看不出来）⇒ 宁可过度串行。
- 「持有者是否在跑门」靠 `kill -0` + `/proc/<pid>/cmdline` ⇒ **非 Linux 平台**退回只看存活。
- 只覆盖 `examples/*/verify.sh`；`selfhost/check_*.sh` 那批守卫**不改源码**，未纳面。
- `run_gates.sh` 的锁块在**脏树检查之后** ⇒ 脏树时不会走到锁（那条路径本来就拒启）。
- 竞态判据是**概率性**的（跑 1 次；10 进程同启 ×100 才等价穷举）。

## 十 分片并行档：默认口径 = **夹住门内并行度**（M309 C1 · 2026-10-17）

> 建立：M309 C1（用户 2026-10-16 11:33 拍板「那就 C1+C3」）。
> 实现：`/data/gatevm/shard_run.sh`（宿主侧调度器，不在仓里）· 逐门裁决器 `shard_verdict.py`
> 发布侧入口：`packaging/chain/shard_accel.sh`（B3 · 路径参数化，缺参 `rc=3`）。

### 十.1 为什么（实测根因，不是推断）

全量门是**每个里程碑都要付的固定成本**：静默串行 214 门 = **9295s（155 min）**。
分片档本该把它摊到 4 路，但 M306 R5 实测只有 **7080s（118 min）**，净加速 **≈1.0–1.3×**、
CPU 时间膨胀 **2.5–3.3×**。

**根因**：分片**没夹住「门内并行度」** —— `run_gates.sh` 的 `GATE_JOBS` 默认 = **本机核数(8)**，
4 路 × 8 = **32 线程抢 8 核**。⇒ 每路负载被抬高 2.5–3.3×，并行收益被超订吃光。
同一根因也解释历史「负载敏感假红」（m183 / m263 / m208 / m296，见 `/data/gatevm/quiet_needed.txt`）。

### 十.2 口径（**默认**，2026-10-17 起）

| 旋钮 | 默认 | 语义 |
|---|---|---|
| `SHARD_JOBS` | **2** | 每路 `GATE_JOBS`（门内并行度上限） |
| `SHARD_CPUS` | 按 N **自动切** N 段连续核区间 | 第 i 路 `taskset -c <第 i 段>`（4 路 ⇒ `0-1,2-3,4-5,6-7`） |
| `SHARD_NO_CLAMP=1` | —— | **退回旧行为**（不夹并行度 / 不绑核），仅用于对照实验 |

⇒ 4 路 × 2 核 × 门内 2 线程 = **8 线程恰好占满 8 核（不超订）**。

### 十.3 实测（同机 · 逐门对拍为准）

| 档 | 编排 | 墙钟 | 逐门结果 |
|---|---|---|---|
| M306 R5（老分片） | 4 路 × `JOBS=8`（32 线程抢 8 核） | 7080s（118 min） | 绿 213 / 红 0 |
| **档A** | 4 路 × `JOBS=2` + 绑核 | 5220s（87 min） | 绿 212 / 红 2（m244 · m302 = 结构性冲突，见十.4） |
| **档A'** | 同档A + **实测负载回灌 LPT** + 两冲突门入 quiet | **5236s（87 min）** | 分片 **绿 213 / 红 0**；quiet 档 8 绿 / 2 偶发红（见十.5） |

⇒ **1.36×**，判据「**≤5400s（90 min）**」达成（原 ≤4200s 的目标已被实测推翻：见十.6）。

### 十.4 结构性冲突：**不能靠「夹」硬扛**的两门

| 门 | 现象 | 定性 |
|---|---|---|
| `m244_gate_parallel` | 494s · rc=1 | 它**自己就是**「测加速比」的门（判据写死 `≥3.0` / `≥1.8`）⇒ 在并行机器上**必然**达不到 |
| `m302_stdlib_surface3` | 901s · rc=124 | 647 例 × 三轨矩阵门，**靠门内并行吃饭**；被夹到 `JOBS=2` 后 389s → **>900s** 撞门自身上限 |

两者同因：**「靠门内并行吃饭」的门不能与「夹门内并行」的分片档共存** ⇒ 必须在**低负载串行档**（quiet）。
⚠️ 但**摘这两门对总墙钟无效**（瓶颈是别的分片的整片负载）⇒ 提速靠**负载均衡**，不是摘门。

### 十.5 覆盖边界（如实登记）

1. **夹并行度 ≠ 消除偶发假红。** m183 / m208 在 **quiet 档（分片早已结束、机器已空）** 仍偶发红；
   随后**空闲单跑复测**（§十一）证明是偶发/宿主边缘 ⇒ 属**另一类**问题
   （GC 压力门在 `PX_GC_STRESS` 判据下的时序边缘），**不是**「4 路并行」造成的。
   ⚠️ 本仓纪律：这类门仍以**判据原文**裁决（不许放宽），只在**归因**上登记，留待单独定性。
2. **quiet 档不是垃圾桶**：进表每条都要有**单跑绿**证据 + 理由（见 `quiet_needed.txt` 表头纪律）。
3. **门清单取自 HEAD**（不是主树）—— 主树可能有别人的未提交新门。
4. **解析器健壮性**：`quiet_needed.txt` / `net_needed.txt` 现支持**行内注释**。
   M309 阶段B 修：旧解析只剥「# 开头」整行 ⇒ A' 日志里出现
   `m208_vm_c_local_roots#追加证据：…` 这种**脏门名**被拼进 `--only`
   （可在 `/tmp/gatevm/m309ab_a2.log` 第 17 行复现）。**数据文件照写，解析器必须健壮**。
5. **裁决器期望集**：串行基线早于某门注册 ⇒ 会被误报「多余门」⇒ 必须**显式登记**
   （本轮补登 `m308_onnx_ops`：它在 `gates.registry.sh:1526` / `ci.yml:1289` **双向在位**、
   `check_gate_registry` 全绿，只是基线 TSV 早于它）。

### 十.8 分片数随核数推导 + 耗时表实测回灌（M351 · 2026-10-28 · 缺陷 613/614）

**根因（实测）**：`4 片 × SHARD_JOBS=2 = 8 线程` 是 M309 在 **8 核机**上设对的常数；
2026-10 换 **16 核**机后没人跟着改 ⇒ 起门后 loadavg ≈ 5.0/16（**一半 CPU 空转**），
M350 那轮墙钟 2h04 = 准备 3min + 分片 1h38 + quiet 29.5min + 发布 ≈5min。

**口径（默认，2026-10-28 起）**

| 项 | 旧 | 新 |
|---|---|---|
| 分片数 | 写死 `4` | **`nproc / SHARD_JOBS`**（16 核 ⇒ 8 片；8 核 ⇒ 4 片，老机行为不变）；夹 2..16；`SHARD_N=` / 位置参数可覆盖；`SHARD_NO_CLAMP=1` 退回 4 |
