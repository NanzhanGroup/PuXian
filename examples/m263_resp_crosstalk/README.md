# M263 · 「响应串味」查到底 + `pbuf`/`fd` 生命周期审查 + **缺陷 466**

## 一 起点：M260 记的「缺陷 440」到底存不存在？

M260 在 m128 门收编后写下：「C10 的 `/list?n=20000` 有概率拿到 `/inv` 形态的 body（**缺陷 440**）」，
并称「M256 源码树同样复现 ⇒ pre-existing」。**本轮把它查到底**，三条独立证据：

| # | 证据 | 结论 |
|---|---|---|
| **[A]** | M257 之后我看到的两份 M256 树日志（`wt_m128_1/2.log`）里的失败**都是** `/inv?kind=list tail=999999` —— 那是**门自己的判据 bug**（M260 已另修），**没有一份**是串味 | 440 的「证据」不成立 |
| **[B]** | 定向复现器（本门）：全新进程 × N 轮 × 每轮 7 条断言，逐字节核「答非所问」 ⇒ **60 轮 / 420 断言 / 零异常**（另加 C9 前戏 30 轮 / 210 断言，同样零异常） | 未复现 |
| **[C]** | 静态审查：串味最可信的机制（连接级余留字节 `pbuf` 在 **fd 复用** 时没清）⇒ 逐点核对 **5 个 `xfree(c->pbuf)` 站点** | 无 fd 复用串味路径 |

⇒ **收口为「未复现」**，并把三类结果都变成**可重复的判据**（而不是一句「应该没问题」）。

## 二 ⭐ 缺陷 466（静态审查当场照出）

串味的机制是：「fd 复用时，上一条连接的残留（**余留字节缓冲** 或 **挂起 handler 项**）被当成
新连接的」⇒ 服务端按旧内容应答。审查发现 **两条关闭路径不对称**：

| 路径 | 清 pbuf | 重置 `c->fd` | **清挂起 handler 表** |
|---|---|---|---|
| `px_evc_close`（统一收尾） | ✅ | ✅ | ✅ `http_pend_clear(fd)` |
| `px_evc_detach`（SSE 用，不 close fd） | ✅ | ✅ | n/a（不 close） |
| **空闲超时关闭（HTTP kind）** | ✅ | ✅ | ❌ **裸 `close(fd)`** |

`http_pend_clear` 的注释原话就是「**防 fd 复用串扰**」（M95-S2）—— 而超时路径没有它。
⇒ **修法**：两个关闭分支补 `http_pend_clear(fd)`（`else { http_pend_clear(fd); close(fd); }`）。

> ⚠️ **可达性未证**（如实登记）：要显形需要「挂起项残留 + fd 复用」同时发生，而连接处于 IDLE
> 时通常没有挂起项。这**不改变**修的理由 —— 与 M213 缺陷 298 同口径：
> 「当前无实际风险，但那是**脆弱性质** ⇒ 按同口径收口」。

## 三 ⭐ 去掉「掩盖」：m128 的 C10

M260 在 m128 的 C10 里写的是「疑似缺陷 440 ⇒ **重试一次** + 打一行 ℹ️」——
**这等于把真发生静默吞掉**（重试成功就继续走，只留一行提示）。
⇒ M263 收紧为「**零重试**」硬判据：一次不符即**判红**并指向取证器。
（判据：`C10_RETRY` 必须为 0。）

## 五 ⚠️ 本轮三个「判据自伤」（都已写进判据注释）

1. **函数定界三轮错**（`funcs_of`）：① 「累积签名直到 `{`」**不重置 pending** ⇒ 一旦某行不含 `{`
   就无限累积、之后再也匹配不上 ⇒ 真仓库扫到 **0 个函数**（全判「?函数」）；
   ② 用「行内有无 `;`」过滤 ⇒ 漏掉单行函数体（`{ return 0; }`）；
   ③ 不排控制关键字 ⇒ `while (cond) {` 被当函数起点、**把整个块跳过去**（只扫到 137/1587 个函数）。
   ⇒ 定稿：**先用括号配平定块，再回扫签名行取名**（两条判据互相独立）。
2. **用子串判「赋值右值」**：`'= NULL' not in nxt` 把
   `c->pbuf = grow; c->pbuf_cap = need_cap; grow = NULL;` 误判成「丢弃」（因为末尾有 `grow = NULL`）。
   ⇒ 必须**解析赋值右值**（`c->pbuf =` 之后到 `;` 之前），不能用子串。
3. **负控只中性化一处判据**：复现器有**两处**独立异常判据（逐字节比对 + 互斥形状），
   只 sed 第一处 ⇒ 第二处仍报 ⇒ 判据自伤负控**假红**。
   ⇒ 收敛到**唯一出口** `flag_anom`，负控整行中性化（也顺带证明了「多出口 = 自伤」）。
4. ⚠️ **门自身 bug**：负控 C 的失明版副本落在 `$W`，而 `repro.sh` 用 `cd "$(dirname "$0")/../.."`
   定位仓库根 ⇒ `$ROOT` 算错 ⇒ 找不到二进制 ⇒ `rc=2`（**不是**「判据失明」）。
   ⇒ 一律把**绝对**二进制路径当参数传进去。

## 六 覆盖边界（如实）

- 复现器用**自建**服务端（`px_serve` + 路由 + 重分配 + 协程），形状对齐 m128 现场，
  但**不复刻** m128 的注入前戏；后者另有 30 轮 / 210 断言的一条记录（见 CHANGELOG）。
- **「串味」这一类故障没有可判定的一般判据**（它是竞态的外观）⇒ 本门给的是
  **可重复的观测窗口** + **生命周期静态审查**；两者都清**不等于**数学上不可能。
- **缺陷 466 的可复现性未做**（需要「挂起项残留 + fd 复用」同时发生）；本门给的是
  静态判据 + 负控（退回原形态必判红）。
