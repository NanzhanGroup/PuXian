# M262（缺陷 464 收尾 + 缺陷 465）· 持锁可失败分配 —— **收口（二）** · 6 → 2

## 一 本轮把 M261 剩下的 4 处**结构性**站点收口

### ① `route_match`（`runtime/runtime_route.c`）

**修前**：整个匹配循环都在 `g_route_mu` 临界区内，而循环体里做的是
`px_dict()` + `px_root_push_keep()` + `px_dict_set(…)` + `px_str(…)` ——
**每个请求**都在临界区内做多次可失败分配（OOM ⇒ 隔离点无法回卷 ⇒ `_exit(1)` 服务中断）。

**修法**：**锁内只读匹配** → 匹配到的路线**快照到栈**（`PxRouteSeg.seg` 是定长 `char[256]`、
段数上限 32 ⇒ `memcpy` 到栈零成本、无指针）→ **锁外**按快照构造 `params`
（`px_root_push_keep` / `px_root_pop` 成对，且在锁外）。

> ⚠️ 快照**只**拷贝段数组；`handler` / `pattern` / 限流参数仍在锁内读出后带出 ——
> `handler` 经全局 `g_routes` 可达（本就是 GC 根，M213 已论证），`pattern` 是指向
> `g_routes[i].pattern` 的 `const char*`（与原实现同一语义）。

### ② `bi_sse_read_line`（`runtime/runtime.c`）

**修前**：两处 `char* tmp = xmalloc(ll+1); … px_str(tmp); xfree(tmp);` 都在
`g_sse_cli_mu` 临界区内。而 **`tmp` 根本不需要** —— `px_str_len` 自己会拷贝字节。

**修法**（三层，全部锁内零分配）：

| 层 | 场景 | 做法 |
|---|---|---|
| ① | **短行**（`< 1024`，绝大多数） | 直接进**栈缓冲** `char small[SSE_LINE_SMALL]` ⇒ 一次堆分配都不要 |
| ② | **长行** | 一只**跨轮复用**的堆缓冲，只在**锁外**增长（`sse_line_grow`） |
| ③ | 备货尺寸 | 取 pending 的**容量上界**（`pend_cap + 1`；容量只增）⇒ **下一轮必然够用** |

新助手：`sse_line_take()`（**持锁调用、绝不分配**；返回 `≥0` 已拷好 / `-1` 需备货 / `-2` 半行）
与 `sse_line_grow()`（**锁外**增长）。轮数上界 8 仅防御「容量在重试间隙又增长」，
真撞上界**响亮**报 `R1009`（绝不静默截断）。

## 二 ⭐ 缺陷 465（本轮由**自写的路由冒烟**当场照出）

M257 的容器守卫把「容器操作的目标类型不符」一律当作「**存储已被 GC 回收并复用**」。

- 对**写入口**（`px_dict_set` / `px_list_push`）：**对的** —— 写非容器**必是 bug**，且
  「拒绝 + 响亮」正是挡住「按失效内存改写 + `xfree` 垃圾指针」这条堆损坏路径的闸。
- 对**读入口**（`px_dict_get`）：**不成立** —— 运行时代码里存在大量**合法的探测式读**，
  典型 `px_dict_get(resp, "headers")`（`px_route_*_respond`），而 `resp` 可以是 **string**
  （handler 直接返回字符串）⇒ 期望结果本来就是 `null`。

**实测**：`route()` 返回非 dict 时**每个请求**刷一条 `[M257-CTR]`（5/5 请求，稳定），
污染 stderr（生产日志 + 性能）。

⚠️ **A/B 对照（决定性）**：`git worktree` 取**干净 M261 树**，编同一个探针 ⇒
**同样 5/5 刷屏** ⇒ **pre-existing**，不是 M262 引入的。

**修法**：读入口**默认静默**（回到 M257 之前的语义 ⇒ 返回 `null`），
仅 `PX_GC_LIVECHK=1` **诊断档**响亮；写入口**保留**无条件守卫。

| 档 | 读入口 CTR | 写入口 CTR |
|---|---|---|
| 默认 | **0** | 仍响亮 |
| `PX_GC_LIVECHK=1` | **5**（探针实测） | 仍响亮 |

## 四·补 ⚠️ **缺陷 467**（M265 追回 · 由 m132 门照出）

本轮的 `bi_sse_read_line` 重写里，我把「**备货重试 ≤ 8 轮**」的计数**顺手用在了主读循环**上：

```c
for (int round = 0; round < 8; round++) {   // ❌ 主循环被限成 8 次
```

而主循环是**流式读**：每来一段「半行」就要再 `recv` 一次（一条 SSE 行可能跨多次 `recv`）
⇒ **8 次 `recv` 后直接返回 `null`** ⇒ **SSE 流被截断**。

**为什么当时没发现**：`m137_sse_connect_ex`（PASS=102）里每行恰好**一次 `recv` 就到位**
⇒ 从没走到第 9 轮；而 `m132_sse_chunked`（chunked 分帧 ⇒ 行跨多次 `recv`）**当场红**。

**修法**：主循环恢复**无界**（`for (;;)`，与原实现一致）；轮数上限**只**绑
`grow_retry`（备货重试）。判据固化进 `check_anchors2.py` 的 **S4/S4b/S8**。

> 教训：**「有界」必须只绑在「重试」语义上** —— 顺手把主循环也套上有界计数，
> 等于把「流式读」变成「最多读 8 次」。

## 五 ⚠️ 本轮踩到的判据自伤（第 5 条，已写进判据注释）

**`strip_comments_strings` 会把字面量内容抹成空格** ⇒ 「存在类」判据一旦涉及字符串字面量
（如 `px_ctr_guard_fail(o, PX_DICT, "px_dict_get")`）就**永远查不到** ⇒ **假红**。
M261 的存在类判据恰好都不含字面量 ⇒ **侥幸通过**。
⇒ 定稿：**存在类 = 只去注释**；**反向类（旧形态 0 次）= 去注释 + 去字面量**。
（同族：M261 的「反向判据命中自己的解释性注释」—— 那次是**多**报了，这次是**少**报了。）
