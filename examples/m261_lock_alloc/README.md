# M261（缺陷 464）· 持锁临界区内的可失败分配 —— **收口（一）**

## 一 病灶与来历

M125/M126 把「运行时错误 / 分配失败」从**进程级**收紧到**请求级**（`longjmp` 回隔离点）。

但 —— **`longjmp` 不展开 `pthread` 锁**。失败点落在临界区内时，回卷会把锁永久留成
「已锁」⇒ 其他线程阻塞 ⇒ 进程**既不服务也不退出（假死）**。M127 因此只能退回
`_exit(1)`（**服务中断** ~3s，好过永久假死，但仍是中断）。

M128 定下修法 = **两阶段**：锁外备货（可失败 ⇒ 请求级 5xx）→ 锁内只发布指针。
实测 M128 修了 3 处，**漏了 `px_str_int_pool`** ⇒ 缺陷 **439**。
M260 修 439（3 处）并建守卫 `selfhost/check_lock_alloc.py`：首扫 **18 处**，修后基线 **13 处**。

**本轮（M261）收口 7 处 ⇒ 13 → 6。**

| # | 站点 | 形态 | 修法 |
|---|---|---|---|
| 1-2 | `fserve_ensure` | 两处 `xcalloc` 在 `g_fserve_mu` 临界区内（懒初始化） | 参数解析与两处分配全移锁外；锁内只「复核 + 发布」，失败即释放备货 |
| 3 | `px_conn_pend_put` | `xrealloc`/`xmalloc` 在 `g_conn_mu` 临界区内 | 探测（锁内只读）→ 备货（锁外）→ 发布（锁内）；**有界重来 ≤4 轮** |
| 4 | `px_pin_obj` | 锁内 `xcalloc` —— 经查是 **不可达死代码** | 删除 + 注释说明为什么不可达 |
| 5 | `px_const_put` | 锁内 `xcalloc`（懒建常量表） | 锁外建好备货，锁内复核 + 发布 |
| 6-7 | `px_rate_limit_try` | 两处 `xmalloc`（建桶 + times 数组）在 `g_rate_mu` 临界区内 | 未命中 ⇒ **出锁**备货 ⇒ 进锁**复核** ⇒ 发布或丢弃 |

> ⚠️ **M262 已把下面 4 处「待收口」全部收口**（见 `examples/m262_lock_alloc2/`），
> 基线从 6 → **2**（只剩两条 `ACCEPTED:`）。本文件以下内容是 **M261 交付当时**的账，
> 按本仓「历史记录不改写」的口径**如实保留**。

## 二 剩下 6 处（M261 交付当时的账）

| 处数 | 站点 | 状态 |

| 3 | `route_match`（`px_dict` / `px_str`×2） | **待收口**（下一轮）：需把匹配段**快照到栈**（`PxRouteSeg.seg` 是定长 `char[256]`），参数构造移到锁外 |

`px_list_push_locked`：`PX_GROW_RETRY_MAX=0` 的对照/退路实现（m128 门 C8/C11 用它做 A/B 对照）。

## 三 顺带修好的**守卫自身两个判据 bug**

这一节是本轮最值得记的部分 —— 守卫是本次的**主要判据**，它自己错了两处：

1. **键里带行号** ⇒ 上游**任何一处编辑**都让基线项整体失配 ⇒ **每次报一堆假新增**。
   实测：只改 `runtime.c`（未改语义）就让 3 条基线项变成「新增」。
   ⇒ 比较键改为 **(文件, 函数, 被调, 类别)** 的**多重集**（`Counter`），**不含行号**；
   行号照旧写进基线（人工定位用）但**不参与比较**。同一函数同被调的 N 处仍按 N 计数。
   （M223 缺陷 324 / M169 缺陷 185 同族的「判据不可判定」。）

2. **跨行签名** ⇒ 只匹配单行 `FN_RX` 会把
   `static int route_match(const char* method, …\n …) {` 整个漏掉，该函数的命中被
   **归到上一个函数名下**（`px_route_has`）⇒ 键错 ⇒ 收口/新增判定都错。（M212 缺陷 289 同族。）
   ⇒ 累积签名行到「括号闭合后的 `{`」。

3. 另：`--update` 只写**一次**每个键 ⇒ 「同函数同被调 N 处」在下一次扫描时变成
   N−1 处假新增。⇒ 改为**按出现次数逐行写出**。

守卫自证由 **5 → 7 条**（新增「行号整体位移不得假新增」「同函数同被调多重集」）。

## 五 ⚠️ 本轮踩到的三个「判据自伤」（都已写进判据注释）

1. **反向判据命中自己的解释性注释** —— 我在收口处写「此处原有 `if (!g_pin_set) g_pin_set = xcalloc(...)`」，
   而反向判据查「该串 0 次」⇒ **假红**。
   ⇒ **内容判定一律先剥注释**（复用 `gcroot_derive.strip_comments_strings`）。
   （与 M200「剥离器要只去注释、保留字面量」同族。）
2. **「首次加锁之前」是错的判据** —— 两阶段的形态是「探测加锁 → **出锁**备货 → 再进锁发布」，
   分配在第 2 次加锁之前、却在第 1 次加锁之后 ⇒ 用「首次加锁之前」判会**假红**。
   ⇒ 正确判据 = 「**不在任何锁区间内**」（按行配对 `lock`/`unlock`）。
3. **中性化只改第一个分支** —— 「判据失明」负控原写 `\b(xmalloc` → `\b(NONE_`，而
   `|xrealloc|xcalloc|…` 仍在 ⇒ 失明**假成立**（负控 C 仍判红，差点误判成「红来路不明」）。
   同族：**数括号不能数字面量里的**（`re.compile(r'\b(xmalloc|…|'` 跨行，字面量里的括号
   让配平永不闭合 ⇒ 该语句一路吞掉后面的行）。
4. ⚠️ **提示文本一律单引号** —— 双引号里的反引号会触发命令替换（本仓第 6 次记）。

## 六 覆盖边界（如实）

- 本门判据都是**静态**；「锁内分配真的会导致 `_exit(1)`」的**动态**证明由
  `m128_unlock_grow`（`PX_ALLOC_FAIL_IN_LOCK` 注入 + 锁审计行）承担，本门不重复。
- 余留字节路径（`px_conn_pend_put`）的动态覆盖在 HTTP 管线化门里
  （`m95_s2` / `m97_s2` / `m131` / `m176` / `m242`）；本门只验 `fserve` / `rate_limit` 两条。
- 未收口的 4 处见 §二。
