## 一 本目录的职责

| 文件 | 职责 |
|---|---|
| `gate_verdict.sh` | **全量门裁决器**（唯一权威）。多路取数、矛盾即报矛盾、**前提自证** |
| `watch_chain.sh` | **通用观察器**：等门（按 PID）⇒ 裁决 ⇒ 绿推 tag / 红挂 p1 |
| `README.md` | 口径与三条纪律 |

⚠️ **各轮不得再自己写判据串** —— 一律调 `gate_verdict.sh`。
判据串是「我想的门输出」；裁决器的前提自证是「门**真的**输出什么」。

---

## 二 `gate_verdict.sh` 的三条硬规矩

① **前提自证**：依赖的词汇（`汇总：失败` / `✅` / `❌` / `⏱`）必须在
   **门实现**（`selfhost/run_gates.sh`）里找得到；找不到 ⇒ `rc=3` **拒绝裁决**。
② **多路一致才裁决**：三路取数求交 ——
   · A 汇总行的失败数
   · B 失败行计数（**`❌` 与 `⏱` 都算** —— 超时门不打 `❌` 但同样 `FAIL++`，只数 `❌` 会漏）
   · C 时序 TSV 里状态非 `OK/SKIP` 的行数
   不一致 ⇒ `rc=2` 报 `INCONSISTENT`，**不许挑一路当结论**。
③ **判红必须列得出红门**：列不出 ⇒ 是判据的问题，不是门的问题（**这正是缺陷 495 的形状**）。

裁决与退出码：

| 裁决 | rc | 含义 |
|---|---|---|
| `GREEN` | 0 | 三路一致为 0 |
| `RED` | 1 | 三路一致有失败，且**红门清单非空** |
| `INCONSISTENT` | 2 | 互相矛盾 / 门没跑完（无汇总行）|
| `PREMISE-FAIL` | 3 | 裁决器与门实现脱节 ⇒ 人工介入 |

实测（M284）：对 **M283 那份被判「红」的真日志** ⇒ `VERDICT=GREEN`（三路 0/0/0）。
再对 6 档夹具（红 / 矛盾×2 / 未跑完 / 超时 / 前提不成立）逐档判对。

## 三 三条纪律（每条都是实测换来的）

1. **等门按 PID，不按日志内容。** 追加式日志里的旧 `FAIL` 行会让「曾经失败」冒充「现在失败」
   —— M280 就是这么自杀的。
2. **state 判据只认 origin 上的 tag**（幂等）。本地文件、日志行都可能陈旧。
3. **`INCONSISTENT` 绝不挂 `m<N>-red`。** 措辞不同是有意的：
   「门红」要去看门；「判据不一致」要去看判据。混在一起会把人带错方向。

## 四 新守卫：`selfhost/check_orchestrator.py`

本目录（以及 `packaging/*.sh` / `selfhost/*.sh` / `tools/*.sh`）现由该守卫扫，三条判据：

| 判据 | 内容 | 形状来源 |
|---|---|---|
| **O1** | `grep …'<串>'` 里的中文判定串，其 **CJK 骨架**必须在仓库其它文件里找得到 | 缺陷 495（凭空串）|
| **O2** | 脚本里 `resolve-topic` 的**第一条**必须早于**第一次跑门** | 缺陷 489（45 分钟 < 门 90–150 分钟）|
| **O3** | 每挂一个 `p1 m<N>-…`，同文件必须有 `resolve-topic m<N>` | 缺陷 489 的另一面（无人了结）|

**O1 口径的校准史（三轮，全部是判据自己的错 —— M283 纪律「口径必须经真仓校准」）**：

| 版本 | 口径 | 真仓结果 | 问题 |
|---|---|---|---|
| v1 | 字面串在**任意文件**在场 | 把 `汇总：失败 0 项` 判成凭空 | **太严**：它由 `run_gates.sh` 打印（模板实例化）|
| v2 | **CJK 骨架**在任意文件在场 | 486 条 · 0 误伤；M283 原件抓出 ✓ | **被自己的取证文本污染** |
| v3 | 骨架必须由**非注释、且非查询行**产生 | **23 条 · 0 误伤**；M283 原件仍抓出 ✓ | — |

⭐ **v2 → v3 的起因是一处自指陷阱**：v2 上线后自证**当场从 5/0 掉到 4/1`** ——
`bad_o1` 不再判红。因为我在**CHANGELOG 的取证段**与 `gate_verdict.sh` 的**注释**里
都**引用**了那个串（作为「它不存在」的证据）⇒ 判据问「这串在仓库里存在吗」，
而**我的证据自己把它变成了存在**。
修法：生产者 = 非注释行（`#` / `//` / `/*` / `*` / `--` 打头跳过）且**不含 `grep`**
（查询它的行也不产生它）。语义也更准：判据串是「某处**会打印**的文本」。
（这一步同时把 `由普贤` 正确放行 —— 它的生产者是 `codegen.px` 的**字符串字面量拼接**，
v2 的「输出关键词」口径会误判。）

**覆盖边界（如实）**：扫描面 = 编排层（`packaging/` · `packaging/chain/` · `selfhost/` · `tools/`，
**67 个 `.sh`**）—— **刻意不含** `examples/**/verify.sh`：实测纳进来多出 **26 条假阳**，
全是「门的判据串来自**夹具文本**」（如 doc 注释 `## 计算两数之和`，生产者在 `.px` 夹具里，
而夹具行是注释/数据）。按「校准到 0 误伤」的纪律**收窄**而非放水。

自证：5 条（4 档夹具 + 1 条反向判据「关掉 O1 ⇒ `bad_o1` 不再判红」）。

**三档用法**：

```bash
python3 selfhost/check_orchestrator.py                 # 真仓扫描（rc=0/1）
python3 selfhost/check_orchestrator.py --self-test     # 自证 5/0
python3 selfhost/check_orchestrator.py --count         # 判定串规模锚点（门用）
python3 selfhost/check_orchestrator.py --probe '<骨架>' # 单骨架在场性（门做对照判据用）
python3 selfhost/check_orchestrator.py --file /tmp/m284/final.sh   # /tmp 编排件启动前自查
```

**扫 `/tmp` 里的脚本**是补上缺陷 490 的最后一段：M283 那次如果跑了
`--file /tmp/m283/watcher283.sh`，会当场得到

```
❌ [O1] 凭空判据串 '双路判据一致：0 红'（骨架 '双路判据一致' 全仓 0 命中）
```

—— **那条假警报根本不会发出去**。
