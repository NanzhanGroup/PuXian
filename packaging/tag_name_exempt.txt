# ============================================================
# packaging/tag_name_exempt.txt —— tag 命名**豁免表**（历史遗留 · 只减不增）
# ------------------------------------------------------------
# 规则（唯一，与 docs/RELEASE_PROCESS.md 一致）：
#     现行（M272 起）：v<次段>.<里程碑>   例：v0.2.271
#     历史冻结：      v<主版本>-m<里程碑>  例：v0.2.0-m167（守卫接受，不再新建）
# **没有补丁后缀**。补丁轮的正确做法：把**同一个合规 tag** 指向该里程碑的最终提交
#   （tag 已推过 ⇒ 用 `git push --force origin <commit>:refs/tags/<tag>` 重定向；
#    ⚠ 不要删 tag 再建 —— GitHub 会把对应 Release 转成草稿）。
#
# 为什么这条规则不能「随意发挥」（2026-10-01 实测事故）：
#   我方误打 v0.2.0-m237s3 ⇒
#     ① packaging/pxrepo_mirror.sh 的版本序正则（同上面这条规则）把它**静默过滤**
#        ⇒ 镜像永远停在旧版，**没有任何告警**（连 ❌ 都打不出来）；
#     ② packaging/build_rpm.sh 的 MILESTONE 取短横线之后**整段** ⇒ rpm 包名被污染成
#        puxian-0.2.0-1.m237s3.el9.x86_64.rpm ⇒ 与 gh-pages 的 `.mNNN.` 交叉校验失配。
#   ⇒ 用户的 dnf 镜像因此停摆（晨曦 2026-10-01 报障）。
#
# 谁在读这张表：
#   · packaging/tag_guard.sh     —— 未登记的违规 tag ⇒ 判红（exit 3）；表里过期条目 ⇒ 判红
#   · packaging/pxrepo_mirror.sh —— 未登记的违规 tag ⇒ 响亮告警（PXREPO_STRICT_TAGS=1 时判红）
#
# ⚠ **只减不增**：新增一行＝人工决定「这个违规 tag 永久保留」。默认动作是**删掉违规 tag**，
#   而不是登记它。历史条目保留的唯一理由：删 tag 会让对应历史 Release 转成草稿，不值得动。
#
